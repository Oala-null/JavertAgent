## Why

用户提供 luo 快速参照分支，并反馈此前补丁后的工作台与详情仍慢。同机合成对照确认发布版缺少 gzip、每次详情重复查询患者来源；62 只读剖析进一步发现同份费用数据在一次详情中重复净额计算10次。现有患者索引已存在。

## What Changes

- 复用 luo 已采用的标准 gzip，并验证 SSE 不缓冲。
- 患者来源短缓存覆盖详情和所有 profile 选源调用；侧栏摘要 TTL 提到60秒，保留先前完成后计时和分页。
- 同请求共享一次惰性费用预处理，保留费用净额/编码/退费和旧审计结果的语义。
- 合成回归及同服务器、同数据的只读前后比较，再按原发布流程部署。

## Capabilities

### New Capabilities

- `workbench-hot-path`: 压缩、来源查询复用与请求内费用预处理上限。

### Modified Capabilities

无公开 API 字段修改。

## Impact

Web main、工作台路由、命中解析器及测试。保留慢病、来源身份、SSE、分页和审计规则；不改已签名院内包、luo 参照分支或数据库索引。
