## Why

现有 2C 结果接口以扁平摘要为主，`hit_codes` 与 `hit_names` 独立去重后无法保证同一位置一一对应，也没有项目发生时间；同时 CLEAN、肿瘤医保限定条件和 Web 卡片的关键展示字段缺少一个稳定、完整的新契约。需要在不破坏现有 `/api/audit/submit` 与 `/api/audit/results/{SYXH}` 的前提下新增 v2，供后续 2C 页面直接还原 Javert Web 卡片。

## What Changes

- 新增独立的 2C v2 提交与结果查询端点，保留 v1 路径、字段和行为。
- v2 接受与 v1 一致的患者数组入参，并明确版本、幂等和轮询终止语义。
- v2 返回所有已完成裁决，包括 `CLEAN`；每条规则形成一张结构化卡片。
- 新增命中项目对象数组，以 `{code, name, occurrence_time}` 为最小关联单元，同时提供严格同索引的 code/name/time 数组。
- 一张卡片可返回多个命中项目；费用/药品命中携带国家码、院内码、原始收费名、限定条件和发生时间。
- 完整返回肿瘤医保资格条件、证明树、方案/范围评价、文书建议和来源版本，使 RD04 卡片可按 Web 工作台还原。
- v2 不输出“暂未描述”等占位文案；无内容字段使用空字符串、空数组或 `null`。
- 行为名称以“两库汇总”H/I 列为主口径；虚构医药服务映射为 `T380206 / 提供不必要的医药服务`，串换保持独立大类。

## Capabilities

### New Capabilities

- `two-c-card-contract-v2`: 定义 2C v2 的端点、入参、轮询状态、卡片结构、命中项目关联、CLEAN 和肿瘤资格完整出参。

### Modified Capabilities

- `rule-registry`: 将虚构医药服务类规则的对外行为认定统一映射为 `T380206 / 提供不必要的医药服务`，串换继续使用独立展示类别。

## Impact

- 影响 `src/javert/web/api/routes_audit.py`、免鉴权路径白名单、命中项目解析器和行为名称配置。
- 新增或扩展 2C 路由、命中项目时间字段及 API 回归测试。
- 更新 `docs/2c对接_javert审计服务.md`，并新增独立的 v2 对接文档。
- 不新增数据库列，不修改既有 v1 URL 和字段，不改变审计裁决逻辑。
