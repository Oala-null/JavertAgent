## Why

Javert 当前规则分散在 163 个 YAML 与多份来源表中，业务专家难以在不理解技术字段的前提下共同核对“原文、系统处理和规则分级”。需要先提供一份简单、可筛选、可批注的协作工作簿，验证专家协作口径，再决定是否建设内部平台。

## What Changes

- 生成一份覆盖当前运行时全部规则的协作工作簿，主表保持一条规则一行。
- 主表只展示 `规则编号 / 原始规则原文 / 我们的处理 / 处理等级 / 专家意见 / 状态` 六列。
- 在 Rule schema 和当前全部 Rule YAML 中新增必备业务字段 `handling_level`，仅允许 `违规（阻断） / 可疑（警告） / 提醒（引导）` 三档，不提供“合规”选项。
- 按“确定性收费规则阻断、临床/资格判断警告、未具备自动处理能力或固定现场核查引导”的口径写入首版分级，作为可由专家后续调整的初始值。
- 将优先级、模板、触发词、工具、预检和来源说明放入独立“技术明细”Sheet，避免干扰专家主视图。
- 保留国家 0325 原始规则、药品派生规则和本地专家扩展规则的来源差异；原文不得被处理摘要覆盖。
- 协作表从 Rule YAML 读取并展示分级；本 change 不修改运行时 `priority`、患者三态 `verdict` 或 2C API 契约。

## Capabilities

### New Capabilities

- `rule-collaboration-workbook`: 从当前 Rule YAML 和可用来源信息形成简单、可筛选、可分级的专家协作工作簿，并执行结构与视觉 QA。

### Modified Capabilities

无。

## Impact

- 影响 Rule schema、当前规则 YAML、规则设计文档、规则加载测试和协作交付物；不改变审计执行、Router、裁决持久化或 2C 出参。
- 工作簿仅包含规则与设计元数据，不包含患者数据、PHI、数据库凭据或环境配置。
- 若试用后需要权限、审核发布、变更审计或自动回写，再另行提出内部平台及 Rule schema/2C 增量变更。
