## Context
gnome-243@7d28b02含首批性能改动；实际Releases中的v1包13项摘要全通过，与仓库清单/安装器一致。用户确认自行拷贝安装，禁止连接院内。院内代码较主干早，原文为全量接口和30秒缓存，上海LIS存在pending分区。

## Goals / Non-Goals
目标是移植本次通用性能能力，并交付不要求先装v1的完整v2。非目标是同步主干全部源码、2C、模型、知识库、临床规则或改变院内取数/退费/锚点语义。

## Decisions
- 只移植性能片段：GZip(保持SSE不压缩)、侧栏60秒与签名失效、同请求费用整理一次、局部导航及60秒/5入口/字符上限详情缓存。既有SQL减载和50人分页随包包含。
- raw接口与LIS分区原样保留，仅加跨导航世代检查，防止迟到原文写入新患者；保留既有30秒原文缓存。院内没有来源profile查询，不添加62专用标签查询。
- v2单独放delivery/web_performance_v2；旧目录、旧manifest和已交付v1包不可变。构建器复用已提交Git树与摘要机制，目标目录存在即失败。
- manifest显式列9个payload文件和已安装日期补丁的完整before映射。仅当该映射及11个日期版依赖匹配时安装；无日期/未知/混合版本拒绝。回滚恢复安装前的日期版。
- 沿用文件白名单、软链接拒绝、批跑锁、同目录进程检查、先全量校验备份后回滚、写失败恢复。配置/数据库/账本/规则不读写，不自动停批跑或重启。
- 只读runtime预检用目标现有Python验证GZip/SSE中间件行为，不导入应用、不读环境实值、不联网；不支持时停止，不自动升级依赖。
- 测试使用冻结LIS、性能v1和日期包代码夹具，v1测试不再引用已变化的当前源码。完整发行摘要仍保留原known-release，再由v2生成叠加后的核验清单。

- 保留原日期版watcher/ledger/checker/known-release四文件字节；新启动入口仅替换运行文件校验目标为日期+性能完整清单，严格验证其它文件不变。原审计context和账本不迁移，升级后用新入口，回滚后用旧日期入口。

## Risks / Trade-offs
现场反馈v2停止脚本与安装器均因同账号进程的cwd不可读中止。新增合成/proc验证：先识别命令，明确无关进程不读cwd；应用候选或命令不可读仍停止，不能直接忽略PermissionError。v2.1只修订安装工具与说明，保留PATCH_ID及9文件摘要，旧v2包不改写，备份和监测context继续兼容。用户手动执行，禁止直接连接医院。

60秒内未获事件通知的变化可能延迟显示，焦点恢复/刷新会失效。旧包尚未安装可直接装v2；非完整已知基线会STOP，不能用force掩盖。文件摘要和本地测试不证明医院进程已加载新代码。

## Migration Plan
先红回归→限定移植→日期基线安装/故障/回滚及未知基线拒绝测试→院内相关组合及合成浏览器验证→提交到gnome-243→从提交构建Releases新目录并校验。用户按包内Bash步骤检查、停止Web/等待批跑、安装、验收、重启；不生成ZIP、不代医院部署。
