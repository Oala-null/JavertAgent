## Context

Section13 Review20 已有 20 个真实冻结病例、四类同类项目意见映射，以及每例当前 Primary 所引用的 2–4 张最小证据卡。现有 Primary 是确定性启发式预填，不是 LLM 个案申诉；combined-deep 使用无网络 companion，也没有调用模型。此次验证只回答一个更窄的问题：给定同类项目的违规内容和审核意见，当前病例已有证据能否支持一段可复核的申诉理由。

病例与同类意见均包含敏感数据，142 连接账号还具备写权限，因此运行器必须在代码层只执行 SELECT、默认只把去标识化最小事实发送到批准的私有模型，并把结果写到 Git 与 Web static root 之外的 0700/0600 私有文件。未脱敏模式必须由显式 CLI 开关开启，并要求用户已针对具体私有端点授权。

## Goals / Non-Goals

**Goals:**

- 对当前活动轮次四类各 5 例，读取当前激活的同类意见映射及该病例现有证据卡。
- 让 LLM 围绕输入意见从证据卡中选择支持事实，输出逐句引用的中文申诉草稿或明确的证据不足结论。
- 在调用前后验证病例归属、最小化、私有模型端点、结构化输出和业务表零变更。
- 产生可审计但不含终端 PHI 的影子运行摘要。

**Non-Goals:**

- 不运行或修改 Javert 规则、Router、precheck、verdict gate。
- 不让模型重新判断审核方是否违规，也不生成政策依据之外的新事实。
- 不新增证据搜索结果、Primary、人工审核修订、申诉材料、工作流事件或后台任务。
- 不部署，不把影子结果写回数据库；只允许本地 hospital-pilot 从私有文件读取展示覆盖层。

## Decisions

1. **同类意见使用已激活映射。** 每例读取 ACTIVE/SOURCE_EXACT mapping 所指向生产来源行的有效违规描述与审核意见：省级 25 列取 `violation_content`/`audit_opinion`，市级 28 列按既有 allegation 契约取 `rule_name`/`machine_opinion`。这把“给出的审核意见”固定为可追溯输入，避免在本次试跑中再做模糊匹配。备选的“从数千行中自动挑第一条”会在 CT、彩超多模板场景产生不可解释偏差，因此不采用。

2. **证据使用当前 Primary 的已有证据卡。** 运行器只读 `evidence_search_result_item` 与 `evidence_item`，每例最多四张；不调用 AnalysisPipeline，不执行新的 playbook 或规则。这样既符合“看现有材料找证据”，也避免任何数据库写入。

3. **单次结构化模型调用。** 每例把违规内容、审核意见和编号为 E1.F1–E4.Fn 的最小原子事实一次性发送给模型。默认脱敏；本次 20 例按用户明确授权使用未脱敏私有模式。模型只返回 disposition、带事实编号的 claims、缺失证据和不确定性；系统把事实编号确定性还原为证据编号及数据库中的逐字短摘，最终 `appealReason` 仅在 APPEAL_DRAFT 时由通过校验的 claims 拼接，杜绝无引用段落。

4. **模型只选择证据，不作规则裁决。** system prompt 明确禁止调用 Javert 规则、禁止补写政策和患者事实、禁止把“未找到”解释为认可扣款。`APPEAL_DRAFT` 必须至少有一个引用当前病例 E 标签的 claim；其他情况返回 `MANUAL_REVIEW` 或 `NO_SUPPORT`。

5. **隐私与端点 fail closed。** 证据始终使用字段白名单和长度上限；默认替换已知患者标识，显式未脱敏模式才保留。端点必须是 loopback 或解析后全部属于 RFC1918/链路本地地址，否则在任何模型请求前终止。

6. **影子结果只落私有文件。** 输出目录必须位于 Git 和 Web static root 之外，目录权限 0700、文件权限 0600。stdout 仅输出类别、成功/失败计数、耗时、token 计数与结果文件路径，不输出病例 ID、意见、证据或申诉理由。

7. **零回写以快照证明。** 运行前后读取当前 Primary 指针、人工修订指针、artifact 指针和关键业务表计数的散列；不一致则整次运行标记失败。数据库连接不用提交型 transaction context，关闭连接时回滚隐式只读事务。

8. **本地同表覆盖层。** hospital-pilot 从显式配置的 0600 私有结果文件读取推理，以标准化 UUID 与当前活动轮次病例精确绑定。20 例直接插入首页同一张紧凑表第一页的最前面，随后是完整院方数据；只在第一列显示“真实案例 N”，不增加独立卡片、分隔标题、置顶徽标或差异化行样式。推理正文两行缩略，以原生悬停提示和键盘聚焦标签提供全文；完整表弹窗使用无圆环的普通小叉关闭。

## Risks / Trade-offs

- [已有证据卡可能遗漏关键材料] → 模型返回缺失证据与人工复核，不把无证据升级为申诉草稿；后续再设计意见驱动的原始 Hub 检索。
- [简单脱敏无法识别所有自由文本实体] → 仅允许批准的私有端点，使用字段白名单、已知标识替换和长标识模式替换；本次不调用公网模型。
- [来源意见与目标病例项目只做到当前映射口径] → 输出保留 mapping 来源散列和免责声明；本次不把同类意见伪装成目标病例原始下发意见。
- [模型输出格式漂移] → 严格 JSON 解析、枚举/长度/引用校验；一次修复仍失败则该例记为失败，不保存未经验证的草稿。
