## Context

跨 FP8 与院内维护线的工作台使用 FastAPI/Jinja/原生 JS/SQL Server。全量侧栏阻塞患者页；历史记录重复传输未渲染 LOB。测试只用合成数据，不连接生产数据库。

## Goals / Non-Goals

目标：患者首屏零全局侧栏查询；侧栏单次最多 50 卡；历史工具调用不传输；专家历史批注、当前证据、筛选语义保持。非目标：规则、模型、2C、数据源口径、DDL 或历史重算。

## Decisions

1. 首屏输出侧栏框架；新增登录保护的 `/api/workbench/patients` 返回分页卡片 HTML、页码、总数和标签。输入防抖并取消旧请求，导航保留筛选和页码。保留短 TTL 的全局轻量计数缓存，因为主诊/费用 facet 来源 CSV，无法直接在结果库统一 SQL 分页；先对全名单摘要筛选排序，再切 50 行渲染。此折衷限制传输与 DOM，但冷摘要查询仍随患者数增长。患者首屏不再等它。
2. SQL 用患者范围 ROW_NUMBER 按 created_at DESC、id DESC 选最新；大字段仅对主卡投影；以最新 verdict 过滤规则。保留全部历史结论和批注。锚点也只取最新规则记录。全量读取接口不变。
3. 沿用现有原文按页签读取；合并同一个请求尚未完成时的重复点击。SSE 更新侧栏按页刷新，不无限插卡；轮询不刷新整页。
4. gnome-243 只移植公共性能逻辑，保留上海来源隔离和 LIS pending。新补丁从已提交树输出新目录，校验旧版和目标文件摘要，备份后覆盖，可回滚；不修改配置、数据库、批跑脚本或旧交付包。

## Risks / Trade-offs

- 冷侧栏仍需全局摘要 → 与详情解耦并复用缓存；不得宣称 SQL Server 现场耗时已测。
- 异步响应乱序 → AbortController 加序列号，只接受最后请求；失败显示重试。
- 旧包与现场可能不同 → 安装前逐文件摘要闸，未知字节拒绝覆盖；保留配置且要求维护窗口停 Web/批跑后安装。
- 合成 SQL 回归使用 SQLite 执行兼容窗口查询 → SQL Server 语法人工核对；真实数据库执行计划与网络耗时属待现场验证。

FP8 回归通过并提交，快进合入 main；独立 gnome 补丁提交后更新原维护线，生成 `JiaZhongXin/Releases` 新版本目录。安装支持 check/apply/verify/rollback；不自动执行远程部署。
