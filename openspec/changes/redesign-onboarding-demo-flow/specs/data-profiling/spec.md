## MODIFIED Requirements

### Requirement: 连接预检

系统 SHALL 提供连接预检(纯计算,不调 LLM):映射好连接键后计算键交集覆盖率,并对时间敏感连接计算时间窗口重叠(揭露化验时间落在住院期外等错位)。预检判据 MUST 为"两个 getter 都能解析得出同一 patient_id"而非简单键集合相等。结论 MUST 给三态:🟢可靠 / 🟡部分匹配可继续 / 🔴键几乎不交挡住。**预检结果 MUST 输出可执行诊断结构**:除三态结论外,MUST 包含每张表的键命中率(`per_spoke`)、命中最低的表标识、以及对零/低命中表的成因建议(列映射错 / 缺桥表),供 GUI 直接定位问题表,而非只给一句"键几乎不交"。诊断数据 MUST 复用既有 `per_spoke` 计算结果,MUST NOT 改 `join_preflight` 核心函数签名(诊断打包在路由层完成)。

#### Scenario: 键交集覆盖率

- **WHEN** 对 5 个患者键做化验表连接预检,4 个命中
- **THEN** 系统 MUST 报告覆盖 80% 并列出未命中键,给🟡结论

#### Scenario: 判据非集合相等

- **WHEN** 文书表键落复合键形态、与费用裸号集合"看似不等",但 `get_notes`/`get_fees` 实际都能解析出同一 patient_id
- **THEN** 预检 MUST 以两 getter 实际解析非空为通过判据,MUST NOT 因键集合形态不同而误判失败

#### Scenario: 时间窗口错位告警

- **WHEN** 病案首页住院期为某窗口,而化验报告时间大部分落在窗口外
- **THEN** 系统 MUST 报告"X% 记录落在住院期外"并给🟡,提示可加日期窗口过滤

#### Scenario: 红灯给可执行诊断而非死胡同

- **WHEN** 连接预检判🔴,其中费用表命中 100%、文书表命中 0%
- **THEN** 预检结果 MUST 含 `per_spoke`(费用 100% / 文书 0%)与"命中最低表=文书"标识,并对文书表给建议(检查患者键列映射 / 是否需经桥表归一),MUST NOT 仅返回单句"键几乎不交"

### Requirement: 日期列逐列格式探测

系统 SHALL 对每个日期列独立探测格式,MUST NOT 设全局 dayfirst。探测 MUST 采样整列(非仅头几行)、按 shape 聚类、寻找 day>12 样本判定 dayfirst;解析 MUST 容忍小数秒精度浮动(.9~.999999)、缺秒、纯日期等变体;MUST 识别"纯时间无日期"列并标记其不可做时间窗口分析;少数派异常 shape(如表头泄漏值)MUST 标红为脏数据。归一结果统一存 ISO。**当某列整列采样仍无 day>12 样本、dayfirst 无法判定时,系统 MUST NOT 静默套用默认 dayfirst(防静默反转数据),MUST 把该列标为"待确认歧义"交由交互确认**;探测 MUST 输出本次所有"待确认歧义"列清单供一次性确认。

#### Scenario: 同文件内不同列不同格式

- **WHEN** 同一来源费用列为 `24/12/2025`(日在前)、文书列为 `2026-01-05`(ISO)
- **THEN** 系统 MUST 分别判定两列格式正确解析,MUST NOT 用一个全局 dayfirst 把其中一列解析错

#### Scenario: 日==月样本不误判

- **WHEN** 日期列头部样本为 `11/11/2025`(无法区分 D/M 与 M/D)
- **THEN** 系统 MUST 继续扫描整列直到出现 day>12 的样本以判定 dayfirst,而非据头几行武断判定

#### Scenario: 整列无 day>12 时交互确认而非静默反转

- **WHEN** 某日期列整列样本均为 1–12(如 `01/05/2025`),扫完整列仍无 day>12 可判
- **THEN** 系统 MUST 标该列"待确认歧义",MUST NOT 静默默认 dayfirst;载入/预检前 MUST 一次性弹确认(列出全部歧义列 + 各列 D/M 与 M/D 两种解析样本对比),用户选定后记入会话日期决策,ETL MUST 据此归一

#### Scenario: 纯时间无日期列

- **WHEN** 某列值形如 `09:28:05.794134`(无日期分量)
- **THEN** 系统 MUST 标记该列"无日期分量",并禁止用它做时间窗口分析

#### Scenario: 表头泄漏标红

- **WHEN** 某日期列含极少数无法解析的值(如字面 `"reportDate"`)
- **THEN** 系统 MUST 把这些异常行标红为脏数据并报告解析成功率
