## Context

R319–R322 是已有 ready 专家扩展规则。预检按费用名子串匹配，Router 还支持弹性关键词/编码，故两处别名不一致可能导致先召回再被判无费用。工作树另有慢病及短标题改动，本次不覆盖。

## Goals / Non-Goals

**Goals:** 用现有 YAML、工具和三态机制完成 9 条规则的 ready 编写交接；输出可逐项手测的证据要求。

**Non-Goals:** 不运行测试/病例/LLM，不改引擎或临床知识资产，不连接数据库或部署服务器，不宣称漏检已实测修复。

## Decisions

1. 保留 R319–R322 ID，补齐收费别名至 trigger/precheck/exam；新建 R323–R326、RD38。新条目不编造全国清单编号或本地收费编码。
2. 计次数必须按服务当日、当地适用的价格内涵、侧别与执行事件核对；ST/费用行数/药瓶数量不能自动等同执行次数。当地规则不明时保留 INCONCLUSIVE，不计算确定违规金额。
3. 虚构服务区分指征、医嘱计划和实际执行，缺记录进入复核，明确取消且未退费等正面证据才支持 VIOLATION。手术收费需核对真实操作及当地映射，术式名称不同不等于分解收费。
4. R321 复用 presence_review；R322 使用中性 coexist_review 并将 AB 合并收费别名纳入两组候选，再由模型确认实际是否同时包含两种检查。R325 也使用中性共存，避免预设目录必然互斥。
5. RD38 以实际同期使用、成分及必要性为核查核心；不以四种药或同属降眼压药直接判违规，不把收费支数当滴药次数。生效条件/特定支付审核仍由既有药品规则负责。
6. 手工重写的 R319–R322 和新增规则 derived_from_template/render_hash 置空，符合 schema 的真实来源定义；尤其联合指征不是 M2 的多次重复检查，不能借模板标签触发单次 CLEAN 闸。重建 mapping 后列为本地专家规则。
7. 仅静态加载/索引一致性/OpenSpec strict 是本期验收，人工病例测试留给用户。为避免政策越界，公开外省目录只做参考，黑龙江条文原件未核实前不作为确定裁决事实。

## Risks / Trade-offs

- [未实测 LLM 与召回] → ready 标明未测试，并给每条人工反例和需补资料。
- [目录工具未输出地区，内涵可能截断] → 需核实目录来源及完整条款；不足时 INCONCLUSIVE。
- [AB 合并收费名存在歧义] → 预检只给候选，不推定两笔收费或重复收费。
- [预检只按名称，未知医院纯编码项目仍可能漏掉] → 文档明确当前限制；手测时补真实非敏感项目别名，不扩引擎。

## Migration Plan

PDF导入纠正：新增 `onboarding/reviewed_pdf.py`，只校验人工复核的完整包，不重造OCR服务。页分类及每页费用行数必须来自原页复核；所有费用和总额使用Decimal校验。发布前调用门禁，备份overlay后按单个去标识病例替换notes/fees，其他行逐字段保持不变；仅新增重跑审计，旧裁决保留。编码不经过文本NER，不能以匹配目录或凑总额方式补造无法读清的字段。

新规则从 drafting 使用 javert mark 升到 ready，重建 Router 与 mapping。生产上线由后续工作按目标环境 runbook 从已提交版本发布；本期无生产迁移。需撤回时按规则状态机回退并重建索引，不改历史裁决。
