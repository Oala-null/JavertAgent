## Why

OCR 病例已经把费用、医嘱和报告文本送入 TP，但 Javert 在费用字段映射、结构化医嘱、诊疗目录和 OCR 报告兜底之间存在断点，导致“数据已识别、规则却看不见”的系统性假阴性。眼科专家复核病例同时证明，现有规则库没有覆盖按计价单位收费、治疗执行举证、床旁设备现场核查和 A/B 超联合指征等场景，必须先补通用证据工具，再补窄规则。

## What Changes

- 补齐费用读侧契约中的计价单位和医嘱关联字段，并保持老 CSV 缺列时兼容。
- 新增医嘱检索工具：优先使用结构化医嘱行；OCR 结构化表为空时，从医嘱类病历全文保守提取候选并明确标记非结构化证据。
- 新增按就诊/收费日期选择有效版本的诊疗目录查询工具；复用仓库已有 2026-04-01、2026-07-01 目录资产并纳入生产部署范围。
- 检验、检查结构化表为空但病历存在报告全文时，现有工具返回显式文书兜底证据，而不是简单宣称“无报告”。
- 增加眼科专家规则，覆盖结膜囊冲洗/眼压次数与计价、睑板腺治疗执行举证、床头心电图设备现场核查、眼 A/B 超联合指征。
- 重建 Router 资产，增加去标识合成回归和一例已发布 OCR 病例的只读回放门禁。
- 不修改历史裁决，不回填患者结果；上线后只影响新审计或明确重跑。

## Capabilities

### New Capabilities

- `clinical-evidence-tools`: 费用单位、医嘱、版本化诊疗目录以及 OCR 报告全文兜底的统一审计证据能力。
- `ophthalmology-expert-rules`: 专家确认的五类眼科收费、执行、指征和现场核查规则及其保守裁决边界。

### Modified Capabilities

- `data-access`: 费用明细新增可选计价单位/医嘱关联字段，Hub 文书合流结构化医嘱，并为检查/检验提供非结构化报告兜底。
- `rule-registry`: 注册新的眼科扩展规则并保持规则来源、状态和 Router 索引一致。
- `routing`: 新规则须按项目名称和国家医保编码召回对应病例，不得因医院项目名后缀不同而漏检。

## Impact

- 影响 `src/javert/data/hub_source.py`、`configs/schema_manifest.yaml`、工具注册与提示词、规则 YAML、Router 生成资产、部署制品范围和相关测试。
- 复用现有 pandas/xlrd 依赖，不新增第三方依赖，不修改 2C/SSE 公共 API，不修改 SQL Server schema。
- Javert 生产部署需要携带两版诊疗目录，重启服务并完成 v3 API、Hub、规则工具和去标识回放验收。
