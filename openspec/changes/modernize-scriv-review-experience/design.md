## Context

当前为Vue3/TypeScript/Vite与FastAPI/SQL Server。App承担页面编排，HospitalDataPanel合并原始清单与20例置前数据，模型补充结果由服务端shadow投影提供。三级流程的原始primaryCandidate仍是提交校验依据。原有改动必须保留。

## Goals / Non-Goals

**Goals:** 三角色共享专业组件、有效建议一致、病例级同步和编辑保护、清晰复审上下文、连续处理、完整表与首屏范围一致。

**Non-Goals:** 不重新运行模型、不改变原始机器结论或人工历史、不迁移数据库、不部署远端；不替换医院证据模板。

## Decisions

1. 增加共享建议展示函数，shadow存在时优先显示其推理处置。原始流程候选保留并在审核校验涉及时标为“流程参考建议”；绝不静默覆盖后端裁决依据。20例的建议排序/筛选在授权scope读取后、分页前应用补充结果；普通全量清单仍走SQL分页。
2. 轮次变化仅触发当前病例detail的版本核对。版本相同保留工作区，版本变化且有编辑才锁表单；无关任务更新只刷新列表。切换、关闭、退出与beforeunload保护编辑。提交可以选择下一条，服务器成功后才跳转。
3. 复审增加独立人工结论区，展示上一级理由与人员信息和证据选择；时间线只追加响应字段并中文展示。复用existing review revision查询与角色scope。
4. 表头保持存在，过滤无结果显示tbody空态。筛选草稿只在应用时成为已生效条件，枚举有搜索和全选。统一金额/日期格式；完整表使用与首屏相同置前行集合，置前排序仍保持用户原要求。
5. 保留Vue和原生控件，新增独立professional样式层及少量共享组件/函数；不引入大UI依赖。Carbon参考：深色48px产品顶栏、灰阶背景、8px间距节奏、直角为主、蓝色主操作。常规表格与审核表单减少卡片嵌套。
6. 分派页保留一个入口，流程与摘要紧凑，负荷图折叠；选择后显示范围与金额，后端门禁保持。病案完整查询折叠至证据之后，审核按钮保持可见。
7. 图片查看器支持适应、原尺寸、放大缩小、滚动/拖动、定位证据区；异步关闭后不回弹。弹层提供Escape与焦点约束。图片来源标记继续保留。
8. 导出明确批次选择，中文状态/排除原因映射、下载反馈，避免技术码进入主操作流程。

## Risks / Trade-offs

- 补充建议与原始流程基准不同 → 明确两者关系并保留严格提交校验。
- 同步与切换异步竞态 → 每次详情/病案请求核对当前case及请求序号。
- 前端字符串契约测试过度依赖旧markup → 更新确已改变的契约，关键同步/建议使用行为测试。
- 当前私有网络或账号不可用 → 本地安全fixture完成浏览器布局及交互验证，真实数据验证边界明确记录。
