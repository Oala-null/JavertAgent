# 本地验收与部署边界

本包为 `gnome-243` 的独立性能补丁，不是 FP8/2C 新功能包。源码从 Git 已提交树读取；`manifest.json.source_commit` 是构建提交，`SHA256SUMS` 覆盖所有交付文件（校验清单自身除外）。

## 性能与兼容

- 合成 1200 患者、1 张当前主卡：院内详情 HTML 从 1,022,767 字节降到 8,474 字节；首屏全局侧栏查询 1→0，侧栏 DOM 从全量变为每页最多 50 人。
- 同规则 8 次审核：大工具记录只传 1 份；其余 7 次的结论、置信度、时间和专家批注保留；锚点只取最新。
- SQL 只读，窗口排序限定当前患者，同时间按 id 取最新。没有执行 DDL、改裁决、重算审计或改动数据库。
- 慢查询完成后开始计算侧栏 TTL，防止查询完成即过期。筛选防抖、取消过期响应、原文请求去重；失败允许重试。
- 上海侧栏继续不读全院 CSV/原文，不显示全局主诊/费用；医院原文接口保留旧响应与 30 秒缓存。LIS 本次住院/pending 分区保持。

## 测试

院内最终组合：194 collected、194 passed、0 failed、0 skipped、0 errors；另有 Node 原文并发/失败重试测试 2 passed，JS/Bash 语法与 OpenSpec 严格校验通过。不是全仓测试统计。

覆盖工作台路由/模板/性能、Web API/鉴权/PHI、原文/命中/概览、事件/心跳、LIS 医疗记录取数/批次/显示/前端、旧包冻结夹具安装/回滚、新补丁安装/故障恢复/回滚/摘要/批跑锁/精确停 Web。

首次宽范围运行原始结果：182 collected、151 passed、10 failed、21 errors、0 skipped。其中外部真实数据夹具缺失、测试会话密钥被夹具清空、旧 v1 构建保护和旧发行摘要与新代码不同均有明确原因。随后将相关测试替换为合成数据、提供测试专用会话密钥、让旧包安装演练从已核验冻结代码构建，并以“旧发行+新性能补丁”校验当前维护线；没有改生产安全闸以迎合测试。

冻结代码夹具 `tests/fixtures/249_lis_v1_code.json.gz` 取自维护基线 `7bb34f9`；旧 LIS payload 摘要逐文件与原签名清单一致。此夹具只有代码，不含 `.env`、配置实值、数据库、患者快照或名单。

浏览器本地合成上海模式验证：侧栏 50 卡、翻页、主诊/费用全局筛选隐藏，当前详情不受影响。FP8 另验证全范围搜索、费用排序、导航保留筛选和错误重试；远端分支合并不等于医院已部署。

## 现场须验证

冷侧栏仍查询全局轻量摘要，SQL Server 索引和网络耗时未在医院测量。每页 HTML/DOM 已有边界；单患者资料本身很大仍可能影响详情或原文。

安装器不改变运行配置、不自动重启、不处理批次名单；`stop_web.py` 仅停止同账号、同目录唯一的 javert web。现场磁盘匹配和进程加载状态必须按 README 单独核验，不能以这些本地测试代替。
