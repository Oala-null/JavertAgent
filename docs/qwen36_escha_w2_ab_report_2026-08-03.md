# Qwen3.6 Escha W2 在 Javert 的部署与 A/B 实测报告

日期：2026-08-03
测试环境：62（NVIDIA RTX 5880 Ada 48 GB）
结论口径：这是部署与技术对照测试，不是临床金标准验证。

> 当前运行状态（2026-08-04）：测试结束后已停止 W2 端口 30002 和 OCR 端口 30001，
> Javert 保持使用端口 30000 的 `Qwen/Qwen3.6-35B-A3B-FP8`。下文有关 W2/OCR 在线的描述
> 仅记录 2026-08-03 测试时状态，不代表现网状态。

## 1. 结论摘要

`EschaLabs/Qwen3.6-35B-A3B-Escha-W2` 已通过 Escha 自带的 SGLang fork 部署到
`127.0.0.1:30002`，测试期间作为隔离试验服务运行，没有切换 Javert 配置，也没有占用
基线端口 30000。测试时 DeepSeek-OCR 同时在线且健康。

显存与磁盘节省是真实的，但“性能不降低”没有在 Javert 负载上复现：

- 模型目录约 12.3 GB，现有 FP8 目录约 35 GB，磁盘下降约 65%。
- 扣除 OCR/GdParse 基础占用后，W2 服务常驻约 29,042 MiB，FP8 常驻约
  41,597 MiB，下降约 30%。W2 能与 OCR 共存，双服务总显存约 36.4–36.9 GB。
- 3 位去标识患者、152 个患者×规则对的主 A/B 中，W2 总墙钟时间为
  1,418.1 秒，FP8 为 723.2 秒；W2 慢 1.96 倍。
- 150 个双方均成功的结果中，裁决完全一致 132 个，一致率 88.0%；若把 W2 的
  2 个失败计为不一致，则为 86.8%。
- 两边 VIOLATION 集合的交集只有 3 条：FP8 共 8 条，W2 共 10 条。以 FP8 作为当前
  运行参考时，W2 新增 7 条 VIOLATION，同时漏掉/降级了 5 条 FP8 VIOLATION。
- W2 已记录的工具调用为 1,665 次，FP8 为 848 次，约翻倍；失败规则退出前的调用
  没有写入该计数，因此 W2 的真实调用量还要更高。最极端的 J90508/R231 为
  453 次工具调用，FP8 同项仅 9 次。

因此，本次建议是：**保留 W2 权重和启动资产供研究，不保持 30002 在线，不切生产，不替换现有 FP8。**
W2 适合继续研究低显存服务，但当前不满足 Javert 对裁决稳定性、工具调用收敛和吞吐的要求。

## 5. 裁决一致性

### 5.1 混淆矩阵

行是 FP8，列是 W2：

| FP8 \ W2 | VIOLATION | INCONCLUSIVE | CLEAN | FAILED |
|---|---:|---:|---:|---:|
| VIOLATION | 3 | 2 | 3 | 0 |
| INCONCLUSIVE | 0 | 2 | 3 | 1 |
| CLEAN | 7 | 3 | 127 | 1 |

- 150 个双方成功结果中，132 个相同，18 个迁移；另有 2 个 W2 失败。
- FP8 的 8 个 VIOLATION 只有 3 个仍被 W2 判为 VIOLATION。
- W2 的 10 个 VIOLATION 中只有 3 个与 FP8 重合。
- 这不是临床准确率：FP8 只是当前运行参考，不是真值。但如此低的 VIOLATION 集合重合度
  足以阻止无人工复核的生产替换。

### 5.2 涉及 VIOLATION 的迁移

| 方向 | 患者 / 规则 |
|---|---|
| FP8 CLEAN → W2 VIOLATION | J18906/R141、R161、R278、R279、RD01；J90508/R007、R160 |
| FP8 VIOLATION → W2 CLEAN | J90508/R141、R146、R155 |
| FP8 VIOLATION → W2 INCONCLUSIVE | J90508/R063、R318 |

其他迁移包括：J66252/R232 I→C；J18906/R103 C→I、R250 I→C；J90508/R080 I→C、
R134 C→I、R165 C→I；J66252/R103 C→FAILED、J90508/R103 I→FAILED。

### 5.3 工具调用不收敛

| 患者 / 规则 | FP8 工具/轮数/裁决 | W2 工具/轮数/裁决 |
|---|---|---|
| J90508/R231 | 9 / 4 / CLEAN | 453 / 8 / CLEAN |
| J90508/R318 | 17 / 7 / VIOLATION | 93 / 11 / INCONCLUSIVE |
| J18906/R278 | 51 / 11 / CLEAN | 84 / 11 / VIOLATION |
| J18906/R143 | 5 / 3 / CLEAN | 30 / 11 / CLEAN |
| J90508/R153 | 3 / 2 / CLEAN | 30 / 11 / CLEAN |

这表明问题不只是 2-bit kernel 的 token/s：模型更容易生成大量或重复工具调用，使 agent
上下文快速膨胀，并改变最终裁决。

## 6. 65k 失败与 131k 定向复测

主 A/B 中两条 R103 失败均为 SGLang HTTP 400：

- J66252/R103：输入 63,628 tokens，加 8,192 输出预算，总计 71,820，超过 65,536。
- J90508/R103：输入 63,711 tokens，加 8,192 输出预算，总计 71,903，超过 65,536。

模型配置的原生上限为 262,144。将试验服务调到 131,072 后，只复跑这两个规则，不落库：

| 患者 / 规则 | 131k 结果 | 轮数 | 工具调用 | 耗时 | 与 FP8 裁决 |
|---|---|---:|---:|---:|---|
| J66252/R103 | CLEAN 0.95 | 4 | 10 | 23.4 s | 一致 |
| J90508/R103 | INCONCLUSIVE 0.50 | 11 | 40 | 79.3 s | 一致 |

因此，131k 消除了硬性失败，测试端点当时保留该设置；但第二项仍显著慢且工具调用多，扩大
上下文不是对 agent 行为回归的完整修复。主 A/B 的 65k 原始数据没有被复测结果覆盖。

## 7. 建议与晋级门槛

当前建议：

1. 不修改 Javert 现有 endpoint/model 配置，不将 W2 设为默认模型。
2. 保留 W2 权重与启动资产；30002 已停止，仅在另行授权的 shadow、提示词兼容或工具调用
   收敛研究中按需启动，不影响 Javert Web 或数据库。
3. 在模型再次晋级前，为 Runner 增加“累计工具调用数、单轮工具调用数、重复调用签名”的
   确定性上限，避免一次响应产生数百次调用；这是代码改动，未包含在本次部署任务中。
4. 对本次 12 个涉及 VIOLATION 的迁移做盲法人工复核，并扩展到更大的去标识病例集。
5. 建议晋级门槛至少包括：0 FAILED、VIOLATION 迁移全部人工可解释、总工具调用不高于 FP8
   的 1.2 倍、墙钟时间不高于 FP8 的 1.2 倍。当前 W2 均未达到。

W2 的低显存价值很明确；如果工作负载是短对话或单轮结构化生成，它仍可能有优势。但对
Javert 这种长 system prompt、多轮工具调用、最终结构化裁决的 agent 负载，本次数据不支持
“性能不降低”的说法。

## 9. 生成内容质量复核（追加，2026-08-03）

### 9.1 复核方法

为避免只用最终标签评价模型，从主 A/B 中选取 20 个高信息量样本生成完整
`reasoning + evidence + tool_calls`，并在当前 131072 上下文配置下连续运行两次：

- 全部 12 个涉及 VIOLATION 的迁移；
- 3 个 FP8/W2 均判 VIOLATION 的样本；
- R231、R153 等标签相同但工具调用异常的样本；
- R103、R232 两个上下文/非 VIOLATION 边界样本。

复核维度包括：最终结构完整性、同配置重跑稳定性、规则 YAML 必做步骤、证据文本与工具返回
的可追溯性、数字主张是否有来源、重复/畸形工具调用。完整内容只在 0700/0600 临时目录离线
审核，以下只保留去敏统计。主 A/B 使用 65536 上下文，质量复跑使用 131072；两者之间的差异
只作为上下文敏感性信号，不再误标为“同配置稳定性”。由于没有为同 20 项重新生成完整 FP8
reasoning，本节能可靠量化 W2 自身质量和裁决差异，不能把每一项 prose 指标都解释成相对
FP8 的精确降幅。

### 9.2 结论：语言可读，但审计结果不可直接自动使用

| 维度 | 结果 | 判断 |
|---|---|---|
| 最终结构 | 20/20 生成合法完整的 `AuditResult` | 格式层可用 |
| 131072 同配置裁决稳定性 | 16/20 verdict 一致；4/20 跨越 VIOLATION 边界 | 仍不可接受 |
| 主 A/B（65536）到首次复跑（131072） | 10/20 verdict 一致 | 存在明显配置/运行敏感性 |
| 12 个关键 VIOLATION 迁移 | 两次同配置复跑有 9/12 一致；分别仅 6/12、4/12 与 FP8 一致 | 高风险 |
| 中间工具格式 | 首次复跑出现 1 次畸形 JSON；第二次未出现 | 有偶发兼容缺陷 |
| 规则确定性步骤 | 8 个典型检验规则中，主 A/B 为 5/8；两次同配置复跑均为 7/8 | 有能力但仍有稳定错误 |
| evidence locator / anchor | 两次分别为 71/71、84/84 非空；anchor 均为 0 | 形式完整，缺精确锚点 |
| evidence 文本强匹配工具返回 | 两次分别为 16/71、21/84；逐字匹配均为 6 条 | 追溯性偏弱且未改善 |
| evidence 弱匹配（四字片段覆盖 <40%） | 两次分别为 31/71、42/84 | 约一半存在明显转述/无来源风险 |
| reasoning 数字主张完全可追溯 | 两次分别为 6/20、8/20 | 不宜直接展示为审计事实 |

证据匹配是保守的文本启发式：去除标点空白后，逐字匹配或计算四字片段在工具返回中的覆盖，
不能代替专家判断；但 Javert 的 evidence 目标本来就是“可定位原文摘录”，因此如此低的匹配度
仍是实际缺陷，而不是单纯文风差异。

### 9.3 具体表现

好的部分：

- 最终 JSON、中文 reasoning、置信度和 evidence 列表均能稳定生成，没有乱码或空答案。
- 典型检验规则所需的 `search_fees`、`note_diagnosis`、
  `scan_progress_indications` 基本都有调用。
- 3 个药品规则样本都执行了自费排查，并按规则追加病理/自费人工复核提示。
- 两次同配置复跑的 8 个典型检验规则均有 7 个最终裁决与确定性的“净正费用 + 诊断指征 +
  病程阳性症状”逻辑一致，说明模型不是整体失去规则理解能力。

不可用的部分：

- 同一模型、温度 0、同一上下文配置和同一数据重复运行，20 个重点样本仍有 4 个改变 verdict，
  且全部跨越 VIOLATION 边界。两个 CLEAN→VIOLATION 样本在相反结论下都给出 0.9 置信度，
  置信度不能用来筛掉这种不稳定。
- 12 个主 A/B 关键 VIOLATION 迁移在两次同配置复跑中仅 9 个保持相同；两次分别只有 6 个、
  4 个回到 FP8 结论，说明偏差不是固定、可校准的单向偏差。
- 检验规则主跑有 3/8 与确定性闸矛盾：例如已有净正收费、无诊断指征且症状扫描为 0 时判
  CLEAN，或症状扫描已有阳性指征时仍判 VIOLATION。重跑时其中部分又恢复正确。
- 同配置两次复跑的 20 项工具调用总数从 1394 次变为 650 次；J90508/R231 从 12 次变成
  385 次但都判 CLEAN，J90508/R007 从 452 次变成 3 次但都判 VIOLATION。相同标签也不代表
  推理过程同质、成本可预测。
- 首次复跑中 J18906/R278 达 434 次、J90508/R007 达 452 次工具调用；第二次虽有下降，
  但 J90508/R231 又升至 385 次。长工具链的停止行为没有稳定下来。
- 出现过形如重复 `name` 字段的畸形工具 JSON。解析器能容错继续，但该轮没有形成有效证据。

### 9.4 可用性分级

- **作为研究/影子输出：可用。** 能观察低显存模型的候选裁决和 reasoning。
- **作为专家草稿：有限可用。** 必须同时展示原始工具证据，并要求人工逐条确认；不能只展示
  reasoning 和 verdict。
- **作为自动违规裁决：不可用。** 当前稳定性、VIOLATION 迁移和证据追溯均未过门槛。
- **作为 FP8 无损替代：不成立。** 文本表面质量没有“全面崩坏”，但审计级可靠性差距很大。

总体判断：W2 的通顺度和结构化输出能力仍在，单次结果中也有相当部分逻辑正确；问题集中在
长工具链下的停止、证据忠实度和裁决可重复性。对普通短对话，这种差异可能不明显；对 Javert
这种需要“同一证据稳定得到同一审计裁决”的工作负载，当前质量下降属于实质性、不可接受。
