LLM 推理

"费用明细中同时存在 CT 增强 (¥300) 和 CT 平扫 4 项 (¥800), 文书中记录了颅脑、上腹部、胸部等多个部位的 CT 检查 (部分标 增强+, 部分标 平扫-). 由于无法确定费用明细中的增强与平扫是否针对同一部位, 无法排除同部位重复收费的可能性, 也无法确认不同部位分别收费的合理性, 故信息不足, 判定为 INCONCLUSIVE."

历史复跑这条 LLM 强判 V conf=0.90 但已标边界. 本次主动退 I conf=0.60 更符合事实 — fee 表确实不带部位字段, 多部位 CT 是合规的, 不能仅凭"4 平扫 + 1 增强" 判定重复. 这是 v0.3 conf 区间收紧 + base prompt INCONCLUSIVE 鼓励的设计意图.

下一步建议

🔴 优先级 1: 修 max_tool_calls 兜底退化 (fix-tool-call-budget-fallback)

R103 J18906 + R080 J13365 暴露同样模式: LLM 探索到 budget 用尽后被 runner 强制兜底成 I conf=0.00 + 空 evidence. 历史这两条本来 V conf=0.90/0.95, 现在退化是 stochastic 抖动 + 新 prompt 让 LLM 更谨慎导致探索代价上升.

选项:

  • (a) 加 retry-with-deadline 机制: tc 触顶时, runner 把 "tool budget 已耗尽, 请立刻输出最终 verdict" 作为 user 消息再发一轮, 强制收敛. 不延长 LLM call 总数, 但给一个出 verdict 的机会.
  • (b) max_tool_calls 从 10 提到 12-15: 简单粗暴, 代价是慢规则更慢, 总耗时上升 20-30%.
  • (c) 给 R103 / R080 加更明确的 prompt_addon: 让 LLM 走指定步骤更快收敛. 治标但不治本 (新规则还可能踩坑).

推荐 (a) + (c) 组合: (a) 是通用兜底, 不影响其他规则; (c) 对已知问题规则定点优化.

🔵 优先级 2: evidence source 集合扩 hospital_config

第二步 R212 J66252 LLM 用 source=etl_warning 引用 hospital_config 是受限选择. base.txt 把 source 集合扩为 {note, fee, drug_indication, etl_warning, hospital_config}, locator 推荐 HOSPITAL_CONFIG: PACU, 让语义更精确.

低成本 (仅改 base.txt + 加单测), 高价值 (R212 / R291 / 未来涉及医院科室的规则都受益).

🟣 优先级 3: 跨患者一致性核查 (add-cross-patient-stats)

本次 17 V 中, R131 / R141 / R143 / R146 在 J18906 + J13365 都 V (跨 2 患者 V 率 100%), R224 同样跨患者 V. 这是系统性违规信号. 应跑 10+ 患者后算每条规则的跨患者 V 率, ≥ 50% 提报到医院级合规整改.

🟠 优先级 4: 多医院切换 hospital_config

当前 demo_hospital hardcoded. 实际部署需 configs/hospitals/{hospital_id}.yaml + patient→hospital_id 映射 + Runner 动态加载. 此项需先有多医院真实数据再做.
