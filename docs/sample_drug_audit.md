## 1. 实测中发现并修复的两个问题 (CLAUDE.md Bug 修复协议: dry-run 端到端验证暴露)

### 1.1 Runner deadline-turn 裸 JSON 不解析 (pre-existing bug, 已修)

dry-run R007/RD24 触顶 (10 轮工具 budget 用尽) 后, deadline turn 输出**裸 JSON** (`{...}`, 无 ```围栏). 旧
`_parse_verdict_block` 只用 `^```json``` fenced 正则匹配 → 合法 verdict (如 `INCONCLUSIVE conf 0.55`)
被当 malformed 丢弃, 落成 **conf=0.00 兜底**. 药品规则因 bulk 多药、探索深而**频繁触顶**, 几乎每条都撞上.

**修**: `runner.py:_parse_verdict_block` 加裸 JSON 回退 (无 fenced 块时取首 `{` 到末 `}`), 多候选择最后一个合法的;
fenced 优先行为不变. `tests/test_runner.py` 加 `test_deadline_retry_accepts_bare_json` 回归.

### 1.2 M8 prompt on-label 过严 + 类型级 evidence 截断 (已调)

- 类型级规则 bulk 命中多药 → 逐药深查耗尽 budget + verdict evidence 数组过长致 JSON 截断.
- on-label 判定过死板: `甲状腺癌` 未逐字写"甲减" → LLM 不敢判 CLEAN, 误落 INCONCLUSIVE.

**调 M8**: ①「类型级收敛」块 (≤6 工具调用, 找到 1 个明确违规即判, 不逐药深查); ② verdict evidence **聚焦 1-3 条**;
③ on-label 闸加「**合理临床外延**算落在依据内」(甲状腺切除→甲减替代; 重症/出血/低白蛋白→人血白蛋白; 化疗→止吐/升白).

**效果 (RD24 甲状腺片 on J66252, 修复前后对比)**:

| | verdict | conf | 说明 |
|---|---|---|---|
| 修复前 | INCONCLUSIVE | **0.00** | deadline 裸 JSON 被丢 + on-label 过严 |
| 修复后 | **CLEAN** | **0.90** | 「甲状腺恶性肿瘤术后→甲减替代→合理临床外延→对症, 不构成超说明书违规」 |

✅ **on-label 误报闸验收通过** (单例): 甲状腺癌患者的甲状腺素片正确判 CLEAN, 证据引病案首页主诊 + 手术记录.

## 4. 结论

1. **on-label 误报闸验收通过 (硬指标)**: 甲状腺批 96 条命中药裁决里, 甲状腺片/钙/类型级 全 CLEAN (0.90-0.95); 2 个甲状腺患者 0 V, 第 3 个仅 1 条真 off-indication V. 闸**按诊断判别**而非按队列一刀切 —— 这是整套设计的命门, 已验证可用.
2. **综合科真违规面真实**: J90508/J94056 共 14 条 V, 抽样 6/8 硬证据 (LLM 主动查 lab 值/生命体征/限定支付字面), 2/8 边缘但方向正确. 药品违规审计从盲区变成可产出.
3. **同名异药/剂型闸有效**: stem 跨剂型匹配带来的同名异药 (注射 vs 口服) 被 M8 剂型复核闸正确拦成 INCONCLUSIVE, 不误判 V.
4. **限二线是最软信号**: 单病历缺一线用药史 → 易偏 V, 运营复核需线下查既往用药 (符合设计 Open Question 预判).
5. **已知残留**: 2/160 (1.25%) 综合科禁忌类规则 deadline verdict 因 evidence 过长截断 → conf=0.00 INCONCLUSIVE (安全, 非误 V). M8 已加 evidence 上限闸把发生率压到极低; 进一步可调 llm_max_tokens 或截断 JSON 修复, 留后续.
6. **runner 裸 JSON 解析 bug 已修** (pre-existing): deadline turn 裸 JSON 不再被丢成 conf=0.00, 惠及所有触顶规则 (不止药品类).

**结论**: M8 药品类规则达到可上线质量, on-label 闸是验收硬指标且通过. R007 从"卡三期"的红区 E 正式解锁, 药品违规审计上线.
