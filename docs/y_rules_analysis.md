**为什么 M1-M6 都不能套**:
- M1 假设两个 fee 项目并存 (主项 + 附属), 但串换是单一 fee 项目被错误命名 (做 X 收 Y, 只有 Y 出现)
- M2 假设无指征过度检查, 但串换的项目本身可能有指征
- M3 限定口腔诊断仅 trivial → 大手术, 不通用
- M4 是按目录量化, 串换的关键是"项目内涵不符"而非"超标准"
- M5 是 fee 有 / section 无, 串换中"section X"和"section Y"都可能无
- M6 是医保限定支付条件, 串换不一定违反支付条件

**M7 模板设计草案** (需要的字段):
- `actual_project`: 实际开展的项目名 (低价 / 普通)
- `billed_project`: 收费的项目名 (高价 / 特殊)
- `actual_indicators`: 文书中能识别实际项目的关键词 (操作过程描述 / 耗材规格)
- `billed_indicators`: 收费项目的特征 (固有耗材 / 操作步骤特征)
- `judgment_logic`: 文书证据指向 actual_project + fee 收 billed_project → V
- 关键工具: search_fees (取 billed_project 价格) + search_notes (取 actual_project 操作描述)
