## 关键实现边界

- 新增规则先写 drafting，再用 `javert mark <ID> --status ready` 前进；既有 ready 不假造验证状态。九条均 P0，优先级只控制审计次序，不代表确认违规。
- R321 使用已有 `presence_review`：目标收费存在即零模型进入外部资料复核，当前不会因人工在病历补一句设备描述自动升级为已验证设备能力。
- R322、R325 使用中性 `coexist_review`。AB组合名称进入两组候选后，仍需核实是否确含两类眼科检查；不能预注“重复收费成立”。
- 手工修订的 R319–R322 及新增规则 `derived_from_template/render_hash` 为空。R322 的联合指征不应套用 M2 多次检查的单次放行闸；其他置信度和证据门控保留。生成 mapping 将九条归为 Javert 独立规则，不依赖 Java 对应规则先命中。
- 当前预检按费用名称匹配，Router 还会按编码/弹性词命中；本次对齐已知别名，但不能保证所有医院的未知名称或纯编码项目都能穿过预检。手测应同时核对 Router 候选、precheck 结果及最终三态，发现新别名后再补 YAML。
- `catalog_lookup` 可按服务日期选版本，但当前返回不含地区证明且项目内涵可能截断。需要受控目录来源和完整条款才能作当地价格认定；没有匹配不能解释为允许收费。
- 费用核对区分净量、全额退费、主项/加收项和独立执行。ST 是医嘱频次，不能直接当计价上限；药瓶支数不能当滴药次数。资料不齐时不推算确定违规金额。
