> 版本: v1.0 | 2026-05-26
>
> 本文档供数据提供方 IT 参考。请按以下规格准备 4 张 CSV/Excel 文件，系统即可完成全自动审计。

## 零、可视化接入（v0.10 推荐，`/onboarding` 工作室）

不再需要手敲 YAML。登录工作台后打开 **`/onboarding` 数据接入工作室**，拖文件 → 连星图 → 看绿灯 → 载入 → 命令行开跑：

1. **上传** — 拖入 CSV/TXT/XLSX，右栏**秒回**抽列（411MB 文件约 12ms：只读表头 + 字节估算行数，
   数值分布点列才算）。文件卡有 **✕** 可删（只删上传文件，不碰你的源数据）。
2. **映射（ER 关系图）** — 左栏是 **ER 关系图**：中间「患者(patient_id)」hub，各表为节点，连线标**连接键**
   （费用/诊断/手术 ← `hsp_account_no`，文书 ← `medcasno`，化验/检查 ← `zyh`，麻醉/病理虚线=视图）。
   国标列名（如 `det_item_fee_sumamt`）会 **fuzzy 命中别名库自动预填**（绿框标注），也可把右栏列**拖到**字段，
   或输入框**联想下拉**。把另一文件的列拖到已绑定的表 → **自动改绑**该表到新文件（不再弹窗拦截）；
   也可「重置映射」或每表「清空」。
3. **声明连接键** — 逐表选 `synth`（裸号合成）/ `asis`（已是落盘形态）/ `bridge`（经病案首页桥表归一，
   适配各表患者键不在同一命名空间）。
4. **连接预检** — 点「连接预检」纯计算给 🟢/🟡/🔴 三态（键交集覆盖率 + 时间窗口重叠），点列还能「列剖析」
   看范围/日期格式/空值率。
5. **载入数据** — 两道闸（必填齐 + 预检非🔴）都过才可点。**注意：本工作台只做映射 + ETL 载入，不在此跑 LLM 审核**。
   点后落映射 + 跑 ETL，把已映射的各表（最多 6 表：费用/文书/诊断/手术/化验/检查）join 成 `data_import/`（按患者），反馈「✅ 文件已载入 — N 表 / M 可审核患者」+
   一条可复制的 `jv-run` 命令。
6. **命令行开跑审核** — `data_import/.loaded.env` 已写好（`JAVERT_SQL_ENABLED=false` → 本地 sqlite-only，
   **不入 142、不上工作台**，纯本地实验）。终端 `jv-*` 命令：

   ```bash
   jv-status        # 看已载入的表 + 可审核患者
   jv-run <患者号>  # 跑单患者 (实时输出)
   jv-run-all       # 跑全部 (前台实时); jv-run-bg + jv-watch 后台+tail
   jv-clear         # 清空 data_import 重新载入
   ```
   首用一次：`echo 'source ~/26er/Javert/scripts/javert.zsh' >> ~/.zshrc && source ~/.zshrc`。

> 真实国标数据（跨命名空间患者键 + 异构日期）接入实测见 `docs/sample_onboarding.md`。
> CLI 等价路径仍在（见第三节末），GUI 与 CLI 共用同一套 ETL/剖析/预检逻辑。

字段必填集合与列序由 `configs/schema_manifest.yaml`（数据模型唯一真相源）统一声明，UI/ETL/工具注册三处共读。

## 一、总览

| # | 数据表 | 说明 | 最少行数建议 |
|---|--------|------|-------------|
| 1 | **费用明细** | 每笔收费一行 | 单患者通常 50-500 行 |
| 2 | **病历文书** | 每段文书内容一行 | 单患者通常 30-200 行 |
| 3 | **病案首页-诊断** | 入院/出院诊断 | 单患者通常 3-15 行 |
| 4 | **病案首页-手术** | 手术/操作记录 | 单患者通常 1-10 行 |

**通用要求**：
- 格式：CSV（UTF-8）或 Excel（.xlsx）均可
- 所有表通过 **患者ID** 关联
- 建议提供 **5-10 位患者**的完整数据（覆盖不同科室/病种为佳）
- 患者姓名、身份证等隐私字段**不需要提供**，用住院号即可

## 三、SQL 兜底接入（142 `aidb` 库，CSV 接入不顺时用）

> 主路径是上面「零」的 `/onboarding` 拖文件。**兜底**：万一现场 CSV 接入不顺，贵院工程师把数据
> **按 `docs/schema` 的 6 张 Excel 模板 1:1 填进 142 `aidb` 库的 6 张 `intake_*` 表**，Javert 直接从
> SQL 取数跑，结果实时进工作台。

**一次性建表**（库已存在，只建 6 张空表）：SSMS 连 `aidb` 跑 `scripts/sql/create_aidb_tables.sql`
（表 `intake_fees / intake_notes / intake_diagnoses / intake_surgeries / intake_labs / intake_examinations`，
列名就是 `docs/schema` 模板表头，全 `NVARCHAR`，幂等可重复跑）。
旧 `intake_fees` 已存在时重跑同一脚本会幂等追加可空“计价单位/医嘱编号”，不会改写既有行。

**工程师填数据**：按 `docs/schema` 6 个 Excel 的「②数据填写」表头往对应 `intake_*` 表插行。
**铁律**：① 住院号 6 表用同一值；② 日期用 ISO `2026-01-05`；③ 列名别改。最小可跑 = 费用 + 文书两表。

**取数 + 跑审计 — 一条命令**（推荐；在 **62 机器上**跑，投资人才能看到原文/费用 tab）：
```bash
# 在 62 上 (62 无 zsh, 用 bash):
cd ~/javert && bash scripts/run_aidb_audit.sh 协和
#   → 拉数+预检 → 跑全部患者 → 结果实时上 62 (批次标签=协和)
sudo systemctl restart javert-web   # 让工作台加载新患者原文/费用/概览 (违规+裁决已实时, 这步补齐原文 tab; 结果在 142 不丢)
# 跑完: 打开 62:8090 → 左侧按批次「协和」筛选, 只看这批新数据的违规
```
> 走 `JAVERT_SQL_ENABLED=true` 上 62，与 onboarding/`jv-go`(本地 sqlite-only) 互不干扰。
> **必须在 62 机器跑**：产出落 62 的 `data_import`，工作台原文/费用 tab 才有数据；在别处跑只把
> "裁决结果"推上 62，原文 tab 空。Mac 本地等价别名：`jv-aidb 协和`（`source scripts/javert.zsh` 后）。

**或手动分步**（等价，便于排查）：
```bash
# 1. 拉数 + 连接预检 🟢 (不写盘先看)
uv run python scripts/etl_from_sql.py --hospital-code 协和 --dry-run
# 2. 实跑, 落 data_import/
uv run python scripts/etl_from_sql.py --hospital-code 协和 --output data_import
# 3. 跑审计 (结果实时入 142 工作台; JAVERT_BATCH_TAG 让投资人一眼认出自己这批数据)
export JAVERT_DATA_DIR=data_import JAVERT_ZD_FILE=shi_zd.csv JAVERT_SS_FILE=shi_ss.csv
export JAVERT_SQL_ENABLED=true JAVERT_BATCH_TAG=协和
uv run javert audit-patient <患者ID> --priority all --use-router --concurrency 5
# 4. 工作台 62:8090: SSE 实时刷出新患者; sidebar 批次 chip=「协和」, facet 一键只看这批
```

> 桥是**快照**（跑前一次性取数 → 转内部 CSV → 跑），不是实时直读 —— 跑批与 DB 解耦最稳。
> 零硬编码列映射（复用 `/onboarding` 同款自动认表）；现有 loader/工具/工作台一行不改。
> 源库由 `JAVERT_SQL_SOURCE_DATABASE`（默认 `aidb`）配置，与结果归档库 `zadig` 区分。


## 四、数据中台接入（142 `sh_yb_platform`，国标 TB_* 表 — DE 取数路径）

> 面向有数据工程能力的院方/合作方：DE 从 HIS/LIS/RIS 取数，**按国标 TB_* 表结构直接入
> 142 `sh_yb_platform` 数据中台**，Javert 使用只读账号消费。`TP_data_hub` 仅是我方开发/回灌
> 对账库；仓库里的推送和索引脚本只允许作用于该自有库。生产中台的建表、索引和写入均由
> DE 走受控变更，Javert 不直接执行 DDL。现行数据集为 23 张表（含扩展表），Javert 用反向
> 取数桥转内部格式跑，zadig_agent 零改动共用产物。

- **表结构与逐表说明**：`Scriv/data_hub_filled/_report.md`（交接报告：全局键体系 + 23 表说明 +
  3 张扩展表逐字段文档）；设计依据 `Scriv/data_hub_关系映射.md`
- **给院方的对接表单**：`docs/试点医院数据对接表单_TB.md`（三档优先级 + 逐表必填字段 + 院方勾选栏，
  含医嘱/处方/影像明细等扩容预留表）
- **取数跑审计**：
  ```bash
  export JAVERT_HUB_DATABASE=sh_yb_platform
  uv run python scripts/etl_from_data_hub.py --all --output data_import_hub   # 或 --patients a,b
  export JAVERT_DATA_DIR=data_import_hub JAVERT_ZD_FILE=shi_zd.csv JAVERT_SS_FILE=shi_ss.csv \
         JAVERT_LABS_FILE=lab_results.csv JAVERT_EXAMINATIONS_FILE=examinations.csv
  uv run javert audit-patient <患者号> --use-router --concurrency 5
  ```
- **同库隔离表族**：当一批结构完全一致的表以固定前缀隔离时，设置
  `JAVERT_HUB_TABLE_PREFIX`；默认空值仍读无前缀 `TB_*`。例如只读
  `TP_data_hub.desus_TB_*`：
  ```bash
  export JAVERT_HUB_DATABASE=TP_data_hub
  export JAVERT_HUB_TABLE_PREFIX=desus_
  export JAVERT_BATCH_TAG=desus
  uv run python scripts/etl_from_data_hub.py --patients <脱敏就诊号> --output <私密临时目录>
  ```
  若同一 workbench 同时展示生产患者与隔离表族患者，不要把全局
  `JAVERT_HUB_DATABASE/JAVERT_HUB_TABLE_PREFIX` 切到隔离源；改用 latest batch tag 的
  显式只读 profile：
  ```bash
  export JAVERT_HUB_RAW_PROFILES='{"desus":{"database":"TP_data_hub","table_prefix":"desus_"}}'
  ```
  仅 `batch_tag=desus` 的患者在 CSV miss 后读取该 profile，其他患者仍读默认 Hub。
  前缀只允许字母、数字、下划线且必须以字母或下划线开头；非法值在查询前失败。
  缺少前缀表时不会回退到无前缀表，避免两批数据静默混源。含临床数据的临时目录须为
  0700、文件须为 0600，审计完成后清理。
- 已验证：sy+szx 8000 患者 631 万行往返无损；J66252 双链路裁决对照 16/18 一致、无 V 级差异
