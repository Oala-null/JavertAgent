批次 1: search_notes 工具边界 + ETL 缺失打标

v0.3 第一步发现 LLM 在 search_notes 全文搜时, 60%+ 假指征命中落在 4 类噪音段 (手术风险告知 / 既往史否认 / 选项框 / 输血告知), 以及 1 例 ETL 数据未数字化但被误判 V. 本批次在工具层做两处修复.

1.2 否认 / 选项框上下文标注

真段 hit 逐条扫上下文窗口

  • [否认段]: keyword 前 40 字符内出现 否认 / 未见 / 排除 / 未发现 / 无明显 → 反向语义. (排除 "无" 因太歧义)
  • [选项框]: keyword 附近 30 字符内出现 □ / ☐ / [ ] → 未必激活.
  • 双标可叠加: [否认段/选项框]

1.3 section 模式 ETL 缺失探测

交叉引用模式

search_notes(section=X) 命中 0 条时, 在全量文书扫 见X / 详见X / 参见X / 见前述X 引用. 有引用 → ⚠️ ETL 警告.

R203 J13365 实锤 (V→I flip)
search_notes(section='麻醉记录') →
⚠️ ETL 数据完整性警告: 该患者无 '麻醉记录' 子阶段, 但其他文书有 2 处引用该记录:
[1] 来源子阶段: 第一手术经过： (引用 '见麻醉记录')

2.1 conf 区间收紧 (base.txt)

原 base.txt

- **confidence**: 你对 verdict 的把握; INCONCLUSIVE 时建议 ≤ 0.5

新 base.txt (5 行展开)

- **confidence**: 你对 verdict 的把握 (v0.3 收紧 conf 区间, 治漂移):
  - VIOLATION / CLEAN: 0.70 ~ 0.95
  - INCONCLUSIVE: 0.40 ~ 0.70 — 不要写 0.0
  - conf = 0.00 仅在极端: 工具全 fail / 关键信息完全缺失
  - 边界规则: 命中部分指征但不充分 → I conf 0.50 ~ 0.60
  - ETL 缺失触发的 I → conf 0.50 (中性保守)

核心思想: 原文本 "≤ 0.5" 被 LLM 解读成 "保险起见 0.0", 现在改成明确区间 + "不要写 0.0" 硬约束.

2.3 三条规则复跑实测 (J66252)

R220 控制性降压 — I conf=0.00 → V conf=0.90

conf 漂移修复

LLM 推理 (新): 患者费用明细中包含 '控制性降压' (¥80)，但诊断仅为甲状腺恶性肿瘤 cT1N0M 及结节，手术为甲状腺癌根治术。手术记录显示出血量仅 2ml，且未提及 '巨大' / '丰富血供' 描述。控制性降压适用于神经外科 / 大血管等高出血风险手术。该患者在无明确指征的情况下收取该费用，构成违规。

R212 PACU 监护 — I conf=0.60 → C conf=0.90

科室配置注入

LLM 推理 (新): 费用检索确认患者 J66252 收取了 '麻醉后复苏监护(PACU)' ¥300 费用。根据提供的医院科室配置信息，该医院 PACU 科室配置为 True，即医院设有麻醉恢复室。规则 R212 的违规核心在于 '医院无麻醉恢复室' 却收取相关费用。由于医院具备 PACU 资质，该收费行为符合诊疗目录规定，不构成违规。

evidence 行:

[fee] 麻醉后复苏监护(PACU): 费用明细出现 ¥300.00

注: LLM 用 source=etl_warning 来引用 hospital config 是受限选择 — 下一步可在 evidence source 集合加 hospital_config 让语义更清晰. 但当前已能正确表达意图.
