🎉 一句话总结

runner 在 for-else 兜底之前加一轮 "deadline" user msg — "已用尽 budget, 立即基于已有 tool result 出最终 JSON, 不要再发 tool_call" — 让 LLM 强制收敛. R103/R080 两条都从 I conf=0.00 救回成 V conf=0.85, 且 evidence 比历史更精细 (因为 LLM 已收集完所有可探索的工具结果, deadline 强制其总结).

设计 + 代码改动

runner.py for-else 加 deadline turn

旧 for-else (step3 末态)

else:
    # for-else: max_calls 用完未 break
    final_reason = "max tool calls exhausted"

新 for-else (step4)

else:
    # for-else: max_calls 用完未 break — 触顶兜底前先发 deadline turn
    # 给 LLM 最后一次基于已有 tool result 出 verdict 的机会.
    # 仅在已经调过工具时尝试 deadline; 完全没调过工具 → 不救, 走旧兜底.
    if tool_records:
        self.emit(
            f"[Runner] tool budget 用尽 ({max_calls} 轮 LLM call, {len(tool_records)} tc), "
            "发起 deadline turn 强制收敛 verdict"
        )
        messages.append({
            "role": "user",
            "content": (
                f"已用尽 {max_calls} 轮工具调用 budget, 你不能再发 <tool_call>. "
                "请立即基于已收集到的 tool result 输出最终裁决 (fenced JSON 块). "
                "若证据真不足支持 V/C, 输出 INCONCLUSIVE conf 0.40~0.60 + evidence 引已查工具结果即可, "
                "不要输出 conf=0.00. 此轮只接受 ```json ... ``` 输出, tool_call 一律忽略."
            ),
        })
        try:
            resp_deadline = self.provider.chat_with_retry(messages)
            content_deadline = resp_deadline["content"] or ""
            self.emit(f"[LLM #deadline] {content_deadline[:1500]}...")
            parsed = _parse_verdict_block(content_deadline)
            if parsed is not None:
                verdict_data = parsed
                final_reason = "tool budget exhausted (deadline verdict accepted)"
            else:
                final_reason = "tool budget exhausted (deadline verdict malformed)"
        except LlmUnavailableError:
            final_reason = "tool budget exhausted (deadline LLM unavailable)"
    else:
        final_reason = "max tool calls exhausted (no tool was called)"

设计要点

要点处理原因
仅在 tool_records 非空时触发 完全没调过工具 → 走旧兜底 base prompt 已强制 ≥1 tool, 完全没调工具说明 LLM 行为异常, 不值得救
deadline user msg 明确禁止 tool_call "此轮只接受 ```json ... ``` 输出, tool_call 一律忽略" 防止 LLM 仍发 tool_call 钻空, 简化解析
给 INCONCLUSIVE conf 区间 "INCONCLUSIVE conf 0.40~0.60 + evidence, 不要 conf=0.00" 对齐 base.txt 第二步 conf 收紧设计, 防止 LLM 偷懒
解析失败走旧兜底 "tool budget exhausted (deadline verdict malformed)" 保留兼容性, 测试可观察新文案
LLM 不可达走兜底 "tool budget exhausted (deadline LLM unavailable)" 不向上抛, audit 完成而非 fail (与 step1/2/3 一致)
正常路径不动 break 出 verdict 的 3 处保持原样 不引入回归; 测试 184 个全过验证
