Javert: 单次 (rule × patient) 的封闭审计回合

Javert 当前 agent 模式是无状态、人工驱动迭代的: 每次 audit 都是一个独立的 LLM 回合, 跑完即结束. 规则(yaml) 是知识载体, 但由人手工编辑 — agent 自己不会修改 yaml 也不会沉淀任何跨次记忆.

核心组件

Runner

src/javert/audit/runner.py

  • 组装 system + user message
  • 循环: LLM chat → 解析 tool_call → 执行 → 反馈结果
  • 无 tool 输出时尝试解析 verdict JSON
  • 一次 repair 兜底, 再失败 → INCONCLUSIVE

ToolExecutor

src/javert/tools/tool_executor.py

  • 文本协议: <tool_call>{...}</tool_call>
  • 4 个工具静态注册
  • per-audit 内存缓存 _cache
  • 无原生 function calling

Rule yaml

configs/rules/Rxxx.yaml

  • 10 字段 pydantic 模型
  • prompt_addon 是规则个性化关键字段
  • 人写, 不是 agent 写
  • git diff 即演进记录

"自我升级" 当前路径 (= 人在环中)

真相: Javert 当前没有 agent 自我升级. 升级回路完全由工程师手动闭环:
  1. javert dry-run R191 --patient J66252 看 trace
  2. 工程师肉眼判断 prompt 哪里弱 / 工具调用是否合理
  3. 手工 edit configs/rules/R191.yaml 的 prompt_addon / evidence_required
  4. 再 dry-run → 满意后 javert mark R191 --status ready
Agent 本身不写任何文件, 跑完一轮即遗忘. 唯一持久化是 audit_runs 表 (只写不读回 LLM, 用于 report).

Hermes: 持续学习的多端 Agent + 程序性记忆 (Skills)

Hermes 是 NousResearch 开源的 agent harness, 核心创新是 agent 把自己学到的工作流当成 Skill 保存下来 — 下次用户提出类似任务时, 同样的"套路"自动加载. 这是真正的 agent-driven self-upgrade.

自我升级核心: skill_manage 工具

关键洞察: Hermes 把"自我升级"实现成了一个普通工具 — agent 在 tool_call 里发起 skill_manage(action="create"|"patch"|"edit"|"delete") 把当前学到的工作流持久化到磁盘. 下一次对话, prompt_builder.py 自动把相关 skill 注入 system prompt.

触发时机 (来自 Hermes 文档):
  • 成功完成需要 5+ 次工具调用的复杂任务
  • 报错后摸索出 working solution
  • 用户纠正了 agent 的做法 ← 这正是你要的"通过用户交互升级"
  • 发现非平凡的工作流

用户交互如何驱动升级 (lifecycle)

1. 用户 → Gateway → AIAgent  (新任务)
2. prompt_builder 注入: SOUL + MEMORY + USER + 相关 skills
3. AIAgent 调用 tools (registry) · trajectory 记录每一步
4. 任务复杂 / 用户说 "不对, 应该这样" / 报错-恢复 → 触发条件命中
5. AIAgent 主动发起 tool_call: skill_manage(action="create", ...)
   ─ 把"做法"写成新的 SKILL.md 到 ~/.hermes/skills/
   ─ 或 patch 已有 skill 修正错误路径
6. session 摘要进 SQLite (FTS5) + MEMORY.md 增补长期事实
7. 下次会话 → prompt_builder 自动加载新 skill, 跳过摸索

两者对比 + 给 Javert 的迁移建议

把 Hermes 的"自我升级 + 用户交互"思想落到 Javert 项目上, 需要先看清两者哪些差异是本质的, 哪些只是尺度问题.

维度Javert (现状)Hermes (目标)
定位 批量合规审计 — 固定规则集跑固定患者集 通用对话 agent — 开放任务空间
用户交互 CLI subcommand 一次性触发, 跑完即退 多端 (CLI/IM/语音), 长会话, slash command + 自然语言
知识载体 configs/rules/Rxxx.yaml — 人工 git commit ~/.hermes/skills/*/SKILL.md — agent 通过 skill_manage 自写
"升级"由谁触发 人 dry-run 看 trace → 手编 yaml agent 自己 在 tool_call 里发 skill_manage
跨次记忆 无 (ToolExecutor cache 只到单次 audit 边界) MEMORY.md / USER.md + SQLite FTS5 全文检索
工具协议 文本 <tool_call> 标签, 自己 regex 解析 原生 function calling (Anthropic/Bedrock/Gemini adapter)
工具规模 4 个 (search_fees / search_notes / note_diagnosis / drug_indication) 70+ tools × ~28 toolsets, 自注册
反馈环 out-of-band: 人看 trace, 改 yaml, 再跑 in-band: 用户在对话里说 "不对" → agent 当场 patch skill

把 Hermes 思想移植到 Javert — 最小可行路径

Step 1 · 让 agent 自己写 rule_addon

新增一个工具 propose_rule_patch(rule_id, addon_diff, reason) — 让 Runner 在 audit 末尾、verdict 之外可选发起. 工具不直接 commit, 而是写入一张 rule_patch_suggestions 表给工程师审阅.

对应 Hermes skill_manage(action="patch") 的弱化版.

Step 2 · 引入用户在环修正

新增 javert chat R191 --patient J66252 子命令: 让工程师在 dry-run 看完 trace 后, 直接对话纠正, agent 把纠正落到 patch suggestion. 不必等再编辑 yaml.

对应 Hermes "user corrects approach → agent patches skill".

Step 3 · 跨次 trace 记忆

建 audit_traces 表 (run_id, rule_id, tool_call 序列, verdict, 耗时). prompt_assembler 在下次跑同 rule 时, 拼入 "上次此 rule 的高效 tool 序列" 作为示范.

对应 Hermes MEMORY.md + FTS5 session search.

Step 4 · trajectory 回放

把现在散在 emit 回调里的 trace 结构化成 trajectory 对象, 失败 audit 可一键复述给 LLM 让它自我归因. 这是 step 1 patch suggestion 的质量基础.

对应 Hermes trajectory.py + error_classifier.py.

评估视角: 你目前已经在 CLAUDE.md 路线图里写到 add-prompt-template-bulk-fit (给 21 个骨架装 prompt) 和 add-parallel-audit. 引入 Hermes 风格的自我升级(上面 4 步) 应该排在它们之后 — 先把 prompt 装满、并发跑通, 再让 agent 自己学会 patch prompt. 否则空骨架上的 self-upgrade 信号会非常嘈杂.

本质差异 / 不能直接照搬的部分

  • Javert 是审计场景, verdict 是结构化输出 — 不像 Hermes 的开放对话, 自我升级必须保留 "verdict 可复核" 这条红线. propose_rule_patch 只能产 suggestion, 不能让 agent 直接改 yaml.
  • Javert 当前用 sglang Qwen3.5, 不走原生 function calling — 短期 skill 注入仍需走 system prompt 拼接, 不能像 Hermes 那样动态注册新 tool.
  • 合规场景对 false positive 极度敏感 — Hermes 的 "5+ tool calls 就建 skill" 启发式不能直接搬, Javert 至少需要 N 次跨患者一致 verdict 才能信一条 patch.
