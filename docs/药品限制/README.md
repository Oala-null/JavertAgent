# 肿瘤药品限制知识库

本目录的三份原始资料用于生成 `configs/oncology_drug_kb.json`，再合并进 Javert 现有的 `configs/drug_audit_kb.json`。

## 依据顺序

每个具体医院药品编码只允许生成一条生效的适应症依据：

1. 医保限定非空：采用医保限定，进入 `限适应症`。生产 `on` 模式下，肿瘤药医保限定候选由 `RD04` 独占；非肿瘤候选仍由 `R007` 处理。
2. 未提取到该产品的医保限定：采用《新型抗肿瘤药物临床应用指导原则（2025年版）》的“适应证”，进入 `超说明书`（RD01）。
3. 医保目录属性未知或非目录：仍保留指导原则条目，同时标为“医保状态待核对”；这不等于确认医保无限定。

同一通用名的不同剂型、目录序号和产品编码分别保留，不能把一个产品的医保限制扩散到另一个产品。
同一院内原始通用名组内先采用医院 2026 产品级限定；医院限定为空时，只有原始通用名全等的国家目录限定可以补位，其他剂型的国家限定只作来源证据。

> 指导原则不是具体厂家的法定药品说明书。知识库只抽取其“适应证”作为说明书侧参考；“合理用药要点”和 `※` 特殊情况下专家共识完整保留在来源层，但不自动作为判违规依据。

## 重建

```bash
uv run --extra kb python scripts/build_oncology_drug_kb.py
uv run python scripts/build_drug_kb.py
```

第一步生成：

- `configs/oncology_drug_kb.json`：医保、医院产品码、指导原则章节及来源页码的完整肿瘤药知识库。
- `output/oncology_drug_kb_review.csv`：目录状态未知、来源冲突、同通用名产品差异等人工核对项。

第二步只把已有生效条目的产品合并到 Javert 主药品库；国家药品码精确匹配优先，不做相似药名或 stem 猜测合并。知识库由进程缓存，重建后需重启 Web / 审计进程。

`无生效条目` 只表示这三份新来源没有形成可覆盖的医保/指导原则依据，不代表药品合规，也不用于撤销 Javert 原有其他药品知识；冲突和缺资料项继续留在核对表。

国家谈判药限制含协议有效期。通用旧链（`R007/RD01-RD03`）跨目录年度审计仍需人工确认适用版本；
`RD04` 肿瘤医保资格 v2 会按就诊日期选择已审核且在有效期内的条件树，找不到适用版本时
fail closed 为 `REVIEW_REQUIRED / DOCUMENTATION_GAP`，不会拿当前版本替代历史版本。所有权、shadow
验收和回滚见 `docs/oncology/operations.md`。
