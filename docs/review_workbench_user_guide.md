# Javert 审核工作台 · 专家使用手册

面向: 医保审核专家  
目的: 对 Javert AI 初判的 **V (违规) / I (不明)** 逐条审核 + 写批复 + 提交入库

---

## 0. 入口

- 内网地址: `http://192.168.31.62:8090/`
- 浏览器: Chrome / Edge / Safari (近一年版本均可)
- 不需要安装任何客户端
- 部署初始基线（2026-05-21）: **106 病人 · 5000+ 裁决 · 529 违规待审**；当前数量以工作台实时统计为准

## 1. 拿账号

**注册已关闭** — 不能自助注册. 由运维统一分配:

1. 联系运维, 提供姓名 + 联系方式 + 科室
2. 运维跑 `javert mssql-user create <你的工号> --display-name "张医生(放疗科)"`
3. 运维告诉你 **用户名** + **初始密码** (一次性, 见下)

打开 `http://192.168.31.62:8090/register` 会看到 "注册已关闭, 请联系运维" 提示页 — 这是设计如此.

---

## 2. 首次登录 + 改密 (重要)

1. 浏览器开 `http://192.168.31.62:8090/login`
2. 输运维给的 **用户名** + **初始密码** → 进工作台
3. **顶栏右上点 "改密"** → 三栏表单:
   - 旧密码 = 运维给的初始密码
   - 新密码 = 你自己想的 (建议 8+ 字符)
   - 再次确认新密码
4. 提交 → 自动跳回登录页 + 顶部绿条 "密码已修改, 请用新密码登录"
5. 用你新密码再登, 进入工作台开始审核

> 改密后 session 会强制清空 (安全默认), 运维也不再知道你的密码. 忘了请联系运维 `mssql-user reset-password <你>` 给新一次性密码.

登录态保持 30 天. cookie 走 `itsdangerous` 签名, 不可伪造.

### Filter (顶部下拉)

| 选项 | 显示 | 用途 |
|------|------|------|
| **违规 + 不明 (默认)** | 只看 V + I 病人 | 主要审核工作 |

Filter 自动写 cookie, 跨会话保持 30 天.

### 病人卡片

- 红色徽章 = Javert 判违规 V 数; 琥珀 = 不明 I 数
- "已审 5/21" = 你 (本账号) 已审 5 条, 共 21 条相关 (V+I)
- 全审完 ✓ 图标 + 浅灰背景
- **(v0.9) 卡片新增**: 主诊断 (一行, 悬停看全文) + `¥费用合计` (大概值) + 相对更新时间 (如 "3 天前" = 该病人最近一次审计)

### 筛选栏 (facet, v0.9 新增)

Filter 下拉下方有一排即时筛选 (纯前端, 不刷新页面, 与 Filter 叠加取交集):

- **主诊关键词**: 输 `甲状腺`, 列表只剩主诊含"甲状腺"的病人
- **费用区间**: `<1万 / 1–5万 / >5万` 按费用合计筛
- **更新时间**: `今天 / 本周 (近 7 天) / 本月 (近 30 天)`
- **tag chip**: 有数据批次标签 (如 `szx`) 时出现, 点亮只看该批次病人 (可多选)
- 任一筛选生效后出现 "✕ 清空筛选"; 病人计数变 `显示数/总数`
- 筛选状态跨病人详情页保持 (同一浏览器会话)

#### 肿瘤药医保资格（RD04）

当规则为 `RD04` 且本次运行已产出结构化结果时，违规卡会额外显示「肿瘤药医保资格」面板。没有该面板不代表合规，只表示该行是旧结果、非 RD04 结果或未启用结构化资格链。

- `audit_disposition` 是审计处置轴：`VIOLATION_FOUND / REVIEW_REQUIRED / NO_VIOLATION_FOUND`。
- `eligibility_status` 是资格满足轴：`SATISFIED / NOT_SATISFIED / DOCUMENTATION_GAP / CONFLICT`。两条轴不能互相替代；例如资料缺失时通常是 `REVIEW_REQUIRED + DOCUMENTATION_GAP`。
- 每项条件状态为 `SATISFIED / NOT_SATISFIED / UNKNOWN / CONFLICT`，并附原因和可展开的证据树。
- 「数据质量提示」说明哪些数据缺失、冲突或无法可靠关联；出现提示时应回看原文或补资料。
- 「病历完善建议」只用于未来规范记录，不能当作患者已经满足条件的证据，也不能据此倒填历史病历。

专家仍使用下方「认同 / 改判不明 / 驳回」三态按钮提交最终复核；结构化面板是核对依据，不替代人工裁定。

#### 命中项目 + 跳原文 (v0.9 新增)

规则描述下方有「命中项目 (N)」块, 把 AI 引用的证据结构化列出:

- 每条显示 `项目编码 · 项目名称` (国家医保码; 鼠标悬停 code 看院内码)
- **药品限定规则** (M8) 额外显示「限定: ...」(医保限定支付原文); 若按通用名匹配到不同剂型/复方, 标 `⚠ 按通用名匹配, 剂型/复方需复核` (提示人工核对, 不当确证)
- 同一通用名命中多个规格 → 按实际计费行分别列出 (各自编码)
- **点任一命中项目** → 右侧 **并排滑出**「原文对照」面板 (不盖住违规卡, 左侧 sidebar 自动收起腾地方, 违规卡留在左边方便左右比对): 自动切到对应页签 (文书/费用)、滚到该段、黄标高亮命中片段。点 ✕ 或 Esc 关闭即复原 (sidebar 回来)。无法精确定位时只切到对应页签并提示"未能精确定位", 不乱标。
- (窄屏面板占比略大但仍并排, 不全屏遮挡。)

#### 评语全文 (v0.9)

其他专家的长评语在列表里截断显 "…", **鼠标悬停即看全文** (无需点开或查库)。

#### 三态决策

| 选项 | 用例 |
|------|------|
| **认同 (V)** | Javert 判违规, 你也认为违规 → 直接确认 |
| **改判不明 (I)** | 证据不足或需补外部数据 (如诊疗目录), 暂不下结论 |
| **驳回 (C)** | Javert 误报, 该收费/诊疗合规 (写明原因) |

#### 评语

- 可选, 但**建议**写, 监管报告会逐条引用
- 中文可输, 无长度限制
- 提交后立刻可见, 其他专家也能看你的评语

#### 修改自己审核

- 已审条目显示绿框 "您的审核: ..."
- 点 **修改** → 表单展开, 填新决策 + 评语 → 提交
- **旧批复不删**, 系统 INSERT 新行 + 自动留 `javert_audit_logs` trail (合规要求)
- 142 表 `javert_vio_review` 同 (run_id, user_id) 多行 + `is_latest=1` 标识最新

## 6. 实时协作 (SSE)

工作台保持长连接, 自动接收事件 (不需要刷新):

| 事件 | 你看到什么 |
|------|----------|
| 其他专家审完一条 | 卡片底部 "其他专家审核" 区增量插入他/她的批复 |
| Javert 跑完一个新病人 | sidebar 顶部 prepend 新卡片 + 右上 toast "新增审计: J88888 R191 → V" |
| Javert 跑完已知病人新规则 | 该病人卡片的 V/I 计数自动 +1 |

> 实现细节: 后台 `audit_watcher` 按 `BIGINT id` 严格递增追踪 (不用 datetime 避免 DATETIME2(7) 精度丢失死循环), 每 1 秒 poll 142, 命中行 fan-out 给所有 SSE 订阅者. 静置 0 推送 / 新 1 行 1 推送, 不重复.

## 8. 导出 Excel

两个入口:

### 8.1 顶栏 "导出" — 全量

`/export?format=xlsx&scope=v_and_i` (默认):

- 4 Sheet (中文名): 审核结果 / 审核进度 / 规则维度 / (可选) 审核历史

- 文件名: `javert_reviews_<ts>_J13365.xlsx`

## 10. 常见问题

**Q1. 我手快点错了"驳回", 怎么改?**  
点该卡片的 **修改** 按钮, 重选 + 重提交. 旧批复不会丢, 但 sidebar 计数 + 导出会取最新 (`is_latest=1` 行).

**Q2. 同时两个专家点同一条 V, 谁的算?**  
都算. 单审制 — 系统不强制达成一致. 监管报告会列两份独立意见.

**Q3. 提交后页面好像没反应?**  
浏览器底栏会闪 toast "已提交". 列表 1 秒后自动刷新. 如果卡了 5 秒以上, F5 手动刷.

**Q4. 我想看到全部病人 (含干净的) 抽查?**  
顶部 filter 切到 **全部 (含干净)**.

**Q5. 怎么搜某条规则?**  
当前版本无 sidebar 搜索 — 用浏览器 Ctrl+F 在 sidebar 找 patient_id, 或在 dashboard 表里看 rule_id. 后续可能加.

**Q6. 凭证安全吗?**  
仅内网部署, 不暴露公网. cookie itsdangerous 签名, 30 天有效. 密码 bcrypt 12 轮哈希, 不可逆. 改密会清空 session.

**Q7. 一个规则比如 R141 在 J13365 跑了 3 次, 我看到 3 张卡吗?**  
不会. workbench 自动 dedup, 同 (rule_id, patient_id) 取 `created_at` 最新一次. 142 raw 行仍保留全部历史.

**Q8. 违规卡顶部的 "肿瘤.重复收费.P0.模板M1" 灰色 chip 什么意思?**  
规则元信息: `{domain}.{violation_type}.{priority}.模板{Mx}`, 鼠标 hover 看该规则的完整 question 描述.

**Q9. 我点了 "查看原始病历" 但文书是空的?**  
极个别老 pilot 病人 (J97491/K00740/K01020) 文书未导入. 主诊 + 手术 + 费用仍可看. 跟运维确认.

**Q10. K00740 这种病人 性别/年龄 显示 "—"?**  
该病人 case_notes 把人口学字段写成 "姓名:某某" 脱敏过, 无法还原. shi_zd 主诊还在.
