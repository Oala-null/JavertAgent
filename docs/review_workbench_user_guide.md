# Javert 审核工作台 · 专家使用手册

面向: 医保审核专家  
目的: 对 Javert AI 初判的 **V (违规) / I (不明)** 逐条审核 + 写批复 + 提交入库

---

## 0. 入口

- 内网地址: `http://192.168.31.62:8090/`
- 浏览器: Chrome / Edge / Safari (近一年版本均可)
- 不需要安装任何客户端
- 部署初始基线（2026-05-21）: **106 病人 · 5000+ 裁决 · 529 违规待审**；当前数量以工作台实时统计为准

## 1. 拿账号

**注册已关闭** — 不能自助注册. 由运维统一分配:

1. 联系运维, 提供姓名 + 联系方式 + 科室
2. 运维跑 `javert mssql-user create <你的工号> --display-name "张医生(放疗科)"`
3. 运维告诉你 **用户名** + **初始密码** (一次性, 见下)

打开 `http://192.168.31.62:8090/register` 会看到 "注册已关闭, 请联系运维" 提示页 — 这是设计如此.

---

## 2. 首次登录 + 改密 (重要)

1. 浏览器开 `http://192.168.31.62:8090/login`
2. 输运维给的 **用户名** + **初始密码** → 进工作台
3. **顶栏右上点 "改密"** → 三栏表单:
   - 旧密码 = 运维给的初始密码
   - 新密码 = 你自己想的 (建议 8+ 字符)
   - 再次确认新密码
4. 提交 → 自动跳回登录页 + 顶部绿条 "密码已修改, 请用新密码登录"
5. 用你新密码再登, 进入工作台开始审核

> 改密后 session 会强制清空 (安全默认), 运维也不再知道你的密码. 忘了请联系运维 `mssql-user reset-password <你>` 给新一次性密码.

登录态保持 30 天. cookie 走 `itsdangerous` 签名, 不可伪造.

医生默认页面按行为认定编码/名称合组，并展示结构化公开解释及默认展开的“审核说明”。审核说明
完整保留已持久化 reasoning 中的收费、诊断、证据缺口和定性理由，只把内部规则号、工具名、
gate/run 术语、英文 verdict 和内部 reason code 中文化或移除；原始 evidence JSON 不在默认页面
渲染。结构化字段不会从审核说明反向猜测，缺少确定来源的内容仍留空或列入“需人工复核”。

#### 肿瘤药医保资格（RD04）

`RD04`（肿瘤药医保限定）的违规卡与普通规则同构：**命中药品（可跳明细表）→ 自然语言推理 → 折叠的「🎯 肿瘤靶向药用药方案合理性」follow-up**。命中的肿瘤药也在「命中项目」里，点它跳明细表定位该药（与其他规则一致）。

点开「肿瘤靶向药用药方案合理性」（默认折叠，摘要带状态徽标：符合 / 不符合 / 待补文书 / 证据冲突）后看到：

- **逐条医保限定核对**：每条用中文条件名（诊断 / 分期 / **病理标志物（免疫组化）** / 既往治疗 / 复发难治 / 移植适合性…）+ ✓满足 / ？文书未见 / ✗不满足 / ⚠冲突 + 原因。
- **🔗 定位原文双链**：某条命中了文书记录（尤其免疫组化）时，原因后带「🔗 定位原文「…」」，点它像命中项目一样右侧滑出原文并高亮那条记录（如 `CerbB2(1+)`）。
- **⚠ 核查生效时间**：若就诊/收费日期在该医保限定声明生效期之外，顶部橙框提示"结果未按生效期过滤，请人工核查该限定当时是否已生效"——这类卡定性前务必先确认生效期。
- **业务元数据**：限定分支、声明生效期、本次就诊日期和依据来源；内部 release/revision、
  concept ID 与证明树不在医生默认页面展示。
- **病历完善建议**：只用于未来规范记录，不能当作患者已满足条件的证据，也不能据此倒填历史病历。

专家仍用下方「认同 / 改判不明 / 驳回」三态按钮提交最终复核；follow-up 是核对依据，不替代人工裁定。

#### 命中项目 + 跳原文 (v0.9 新增)

规则描述下方有「命中项目 (N)」块，只列与患者实际资料确定关联的项目：

- 每条显示 `项目编码 · 项目名称` (国家医保码; 鼠标悬停 code 看院内码)
- **药品限定规则** (M8) 额外显示「限定: ...」(医保限定支付原文); 若按通用名匹配到不同剂型/复方, 标 `⚠ 按通用名匹配, 剂型/复方需复核` (提示人工核对, 不当确证)
- 同一通用名命中多个规格 → 按实际计费行分别列出 (各自编码)
- 费用/药品项必须关联患者实际收费组且退费抵消后净数量大于 0；只在检索词或内部证据中
  出现、患者没有对应收费行的名称不会冒充“命中项目”。
- **点任一命中项目** → 右侧 **并排滑出**「原文对照」面板 (不盖住违规卡, 左侧 sidebar 自动收起腾地方, 违规卡留在左边方便左右比对): 自动切到对应页签 (文书/费用)、滚到该段、黄标高亮命中片段。点 ✕ 或 Esc 关闭即复原 (sidebar 回来)。无法精确定位时只切到对应页签并提示"未能精确定位", 不乱标。
- (窄屏面板占比略大但仍并排, 不全屏遮挡。)

#### 评语全文 (v0.9)

其他专家的长评语在列表里截断显 "…", **鼠标悬停即看全文** (无需点开或查库)。

#### 三态决策

| 选项 | 用例 |
|------|------|
| **认同 (V)** | Javert 判违规, 你也认为违规 → 直接确认 |
| **改判不明 (I)** | 证据不足或需补外部数据 (如诊疗目录), 暂不下结论 |
| **驳回 (C)** | Javert 误报, 该收费/诊疗合规 (写明原因) |

#### 评语

- 可选, 但**建议**写, 监管报告会逐条引用
- 中文可输, 无长度限制
- 提交后立刻可见, 其他专家也能看你的评语

#### 修改自己审核

- 已审条目显示绿框 "您的审核: ..."
- 点 **修改** → 表单展开, 填新决策 + 评语 → 提交
- **旧批复不删**, 系统 INSERT 新行 + 自动留 `javert_audit_logs` trail (合规要求)
- 142 表 `javert_vio_review` 同 (run_id, user_id) 多行 + `is_latest=1` 标识最新

每个病人详情顶部按钮 **查看原始病历** → 弹 modal:

```
┌─ J13365 · 原始病历                                            × ─┐
│ 主诊: 肺恶性肿瘤 (C34.x00)                                       │
│                                                                  │
│ ┌─ [文书] [费用] [检验记录] ─────────────── ← 按 tab 加载         │
│ │                                                                │
│ │ ┌─ [搜索 (Ctrl+F / ⌘F) — 当前 tab 内高亮跳转] 3/15 ↑ ↓ × ┐ │
│ │ └──────────────────────────────────────────────────────────┘ │
│ │                                                                │
│ │ 阶段 / 子阶段 / 时间 / 内容  ← 高亮命中处                      │
│ └────────────────────────────────────────────────────────────────┘
```

| 操作 | 行为 |
|------|------|
| 点 **文书** / **费用** / **检验记录** tab | 首次切换才加载该页签，已成功内容在当前页面缓存 |
| 键入关键词 | 120ms 防抖 → 当前 tab 内所有命中加黄背景, 第一个高亮琥珀 |
| **Ctrl+F / ⌘F** | 拦截浏览器搜索, focus 工作台搜索框 |
| **Enter** / **↓** | 跳下一个 |
| **Shift+Enter** / **↑** | 跳上一个 |
| **Esc** | 搜索框有内容 → 清空; 否则 → 关 modal |

点命中项目时，页面会先加载锚点对应页签，再尝试定位和高亮；费用跳转不等待文书或检验查询。
三种提示含义不同：

- “原文源暂不可用”：上游或查询超时，点击“重试”会重新请求，失败结果不会写入缓存。
- “未找到该患者的原始数据”：已确认是真实无数据，不应不断重试。
- “未能精确定位”：页签数据已加载，但锚点过期或文本变化；可在当前页签手动搜索。

反馈故障时只提供页面、目标页签、提示类型和大致时间，不要在截图或消息中附患者原文、
数据库连接信息或完整请求内容。

## 6. 实时协作 (SSE)

工作台保持长连接, 自动接收事件 (不需要刷新):

| 事件 | 你看到什么 |
|------|----------|
| 其他专家审完一条 | 卡片底部 "其他专家审核" 区增量插入他/她的批复 |

| Javert 跑完已知病人新规则 | 该病人卡片的 V/I 计数自动 +1 |

> 实现细节: 后台 `audit_watcher` 按 `BIGINT id` 严格递增追踪 (不用 datetime 避免 DATETIME2(7) 精度丢失死循环), 每 1 秒 poll 142, 命中行 fan-out 给所有 SSE 订阅者. 静置 0 推送 / 新 1 行 1 推送, 不重复.

## 10. 常见问题

**Q1. 我手快点错了"驳回", 怎么改?**  
点该卡片的 **修改** 按钮, 重选 + 重提交. 旧批复不会丢, 但 sidebar 计数 + 导出会取最新 (`is_latest=1` 行).

**Q2. 同时两个专家点同一条 V, 谁的算?**  
都算. 单审制 — 系统不强制达成一致. 监管报告会列两份独立意见.

**Q3. 提交后页面好像没反应?**  
浏览器底栏会闪 toast "已提交". 列表 1 秒后自动刷新. 如果卡了 5 秒以上, F5 手动刷.

**Q4. 我想看到全部病人 (含干净的) 抽查?**  
顶部 filter 切到 **全部 (含干净)**.

**Q5. 怎么找某类问题?**
优先按页面上的行为认定名称和三态筛选；医生默认页面不显示内部规则号。

**Q6. 凭证安全吗?**  
仅内网部署, 不暴露公网. cookie itsdangerous 签名, 30 天有效. 密码 bcrypt 12 轮哈希, 不可逆. 改密会清空 session.

**Q7. 同一个审核问题跑了 3 次, 我看到 3 张卡吗?**
不会。工作台按内部审计键取最新一次结果，历史记录仍保留用于受控追溯。

**Q8. 为什么卡片不再显示规则号和原始证据 JSON?**

## 查看慢病试跑

在患者列表选择“慢病”标签，进入病例后使用“全部”查看CD评估。“慢病命中（待复核）”表示找到可定位的候选证据，不表示已经符合认定标准；“未发现慢病候选证据”也不等于排除该病。慢病面板保留政策版本、逐节点状态、缺失材料和OCR质量提示；点击/查看来源定位可回到相应扫描页文字。未经人工核对的OCR日期、数值与否定表述须由专家复核。慢病评估不计为普通医保违规，现有审核和评论操作保留。
