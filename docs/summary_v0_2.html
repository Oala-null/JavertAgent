concurrency 选型建议

concurrency规则数预估耗时风险建议
1 (串行) 1-5 条 ~80s/条 无 dry-run 单规则 sanity check
3 10-20 条 ~3-5 min 无 开发期默认
5 20-50 条 5-11 min sglang 偶尔 timeout (重试可恢复) 生产推荐 ✅

缓存收益 (share-tool-cache)

跨规则共享 ToolExecutor 缓存. note_diagnosis(J66252) / search_fees(category=手术类) 等被多条规则同时调用时, 后续规则直接命中缓存.

组 F 在并发 3 + cache 下 hit_rate 62.5% 最高; 组 G/I/J 在并发 5 + 模板异构下 hit_rate 33-39% (因 M5 多 section search_notes 不易共享).

每次跑 audit-patient 前 cache reset; 同一 patient 跨 rule 共享, 跨 patient 重新预热.

🥇 诊疗目录 / 医保支付目录 — 解锁 31 条

难度低 · 投入小 · 收益最大

来源: 国家/省级医保局公开的医疗服务诊疗目录 (含项目编码 + 内涵 + 计价单位); 各省《医疗服务诊疗目录》通常 PDF/Excel 可下载.

工具设计: service_catalog(query: str) 返回项目内涵 + 计价单位 + 同切口规则等. 集成方式类似现 drug_indication 表.

解锁规则: M4 12 条 (R020/R063/R074/R165/R212/R250/R291/R292/R293 + 已 init R193/R196/R200), 加上 R201 串换 + 19 条红区 E.

预期工作量: 1-2 周 (数据清洗 + 工具实装 + m4-rollout).

🥈 药品说明书 + 医保限定支付 — 解锁 ~10 条

难度中 · 数据已部分可得

来源: 国家药监局药品说明书 API (公开); 医保药品目录 (年度更新, 含限定支付条件).

工具设计: 扩展现有 drug_indication, 加 get_drug_label(name) 返回 (适应症 / 限定条件). 现有 51 种药品表可作 seed.

解锁规则: R007 (超说明书) + 红区超说明书药品规则.

预期工作量: 2-3 周 (说明书结构化清洗 + 限定条件解析).

暂不建议补 (难度高, 解锁少)

  • 身份核验 (R284, 仅 1 条): 需医院 HIS 系统对接 + 患者人脸/身份证, 涉及隐私合规, 投入产出比低
  • 行为审计 (R280/R281): 需调监控/财务/电话记录, Javert 框架内做不了, 建议交给现场审计
  • ICD 编码篡改检测 (R283): 需大量历史病例 + ICD-10 主诊断逻辑, 学术难度高
  • DRG 分组器 (R012): 商业分组器 ¥20w+, 可考虑接 grouper service, 但需 ICD 完整链路
